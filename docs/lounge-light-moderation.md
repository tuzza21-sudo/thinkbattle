# 가벼운 진행: AI는 시작을 돕고 물러난다

2026-10-06 변경. 그룹 대화의 주인공은 사람이다. AI는 첫인사, 자기소개, 첫 이야기의 공평한 시작을 돕고 그 뒤에는 부를 때만 짧게 말한다. 1:1은 진행이 아니라 주고받는 대화다.

## 그룹 흐름 (2~6명)

| 단계 | 진행 | AI 발언 |
| --- | --- | --- |
| 0 서로 알아가기 | 한 사람씩 차례, 패스 가능 | 첫인사 1회: 2~3문장·180자 이내. 주제를 한 구절로 소개하고 가벼운 자기소개를 부탁하며 패스 안내는 여기서만 |
| 1 첫 이야기 | 3명 이상은 한 바퀴 차례 뒤 자유 대화, 2명은 바로 자유 대화 | 1회: 1~2문장·150자 이내. 자기소개에서 실제로 겹친 점 하나를 짚고 첫 질문 |
| 2~4 이야기 카드 | 자유 대화. 방장이 `다음 이야기 카드`로 넘긴다 | 없음. 카드는 화면에만 표시 |
| 5 마무리 | 방장이 `마무리하기`를 누르면 한마디씩 차례 | 1회: 1~2문장·120자 이내 |

- 자유 대화에는 타이머가 없다. 30분이 지나면 방장 화면에만 마무리 안내가 보인다. 방 자체의 1시간 만료는 기존과 같다.
- 차례가 끝난 뒤 AI가 각자의 발언을 정리하는 단계(`summarizing`), 자유 대화 종료 예고(`free_ending`), 시간에 맞춘 자동 주제 전환은 없앴다.
- 정해진 AI 발언은 방 전체에서 3회다. 이전에는 14회였고, 4개 주제마다 소개·정리·종료 예고가 있었다.

## AI가 말하는 조건

| 상황 | 동작 |
| --- | --- |
| 사람이 말을 마침 | 그룹: 응답하지 않는다. 1:1: 짧게 반응한다 |
| `AI 도움` 버튼 | 말문 열어줘 / 질문 하나 / 다른 화제 / 지금까지 정리 중 고른 한 가지만 한다. 이야기가 2초 이상 멈췄을 때 말한다 |
| "사회자, 어떻게 생각해?" "도우미야, …" | `direct`로 저장한다. 그 질문에만 짧게 답한다 |
| 긴 침묵 (그룹 자유 대화) | 사람 음성 40초 없음, 마지막 사람 전사 30초 이상 전, AI 발언 120초 이상 전, AI 발언 뒤에 사람이 말한 적이 있을 때만 질문 하나를 건넨다. 같은 침묵에는 다시 말하지 않는다 |
| 긴 침묵 (1:1) | 먼저 말을 걸지 않는다. `화제 하나 던져줘` 버튼으로 새 화제를 부탁한다 |
| AI가 말하는 중 사람이 말함 | 0.4초 이상 이어지는 목소리면 AI 음성을 멈추고 그 사람의 말을 녹음한다 |
| 침묵 개입을 준비하는 중 사람이 다시 말함 | 생성된 응답을 재생하지 않고 오류도 표시하지 않는다 |

역할은 방 정원으로 정한다. `capacity=1`은 대화 상대이고, 그룹 방은 일부 참가자가 앱을 벗어나 연결된 사람이 한 명뿐이어도 도우미 역할을 유지한다. 서버의 `claim_voice_lounge_host`와 브라우저의 `nextLoungeHostReason`이 같은 규칙을 쓴다.

## 프롬프트

- 1:1: 진행자 설명 대신 진행자별 `companion` 말투(`src/lib/lounge.ts`)를 쓴다. 매번 질문하지 않고, 의견을 물으면 하나의 관점으로 먼저 답한다. 140자 이내라는 기존 길이 규칙을 유지한다.
- 그룹: 진행자 설명은 말하게 된 순간의 말투에만 쓴다. 한 번에 질문은 하나까지다. 조용한 사람을 지목하거나 각자의 발언을 나열하지 않는다. 요청 종류별 길이를 지정한다.
- 공통: 안전·분야·스포일러·사전 자료·장면 카드 규칙은 기존과 같다. 최대 출력 토큰은 1400/900에서 700으로 줄였다.

## 끼어들기 (barge-in)

`src/lib/useLoungeAudio.ts`의 `loungeBargeIn` 값을 쓴다. 원격 참가자는 RMS 0.06 이상, AI를 직접 재생하는 기기(방장·1:1)는 자기 스피커 소리를 듣기 때문에 0.09 이상이어야 하고, 둘 다 0.4초 동안 이어져야 한다. 원격 참가자는 LiveKit 데이터 메시지(`lounge-barge-in`)로 방장 기기에 중단을 요청한다. AI 음성 중에 시작한 사람의 녹음은 AI 음성 때문에 잘리지 않는다.

AI가 중간에 멈춰도 대화 기록에는 생성된 전체 문장이 남는다. 스피커로 크게 듣는 휴대폰에서는 에코 제거 성능에 따라 AI 소리 때문에 멈추거나, 사람 목소리가 작으면 멈추지 않을 수 있다. 실제 기기에서 값을 조정해야 한다.

## 적용 순서

1. SQL Editor에서 `supabase/migrations/20261006000000_voice_lounge_light_moderation.sql` 전체를 실행한다(`20261005000000` 이후). 진행 중인 `summarizing` 세션은 자유 대화로 바뀌고 `free_ends_at`은 비워진다. 다시 실행해도 안전하다.
2. API와 클라이언트를 함께 배포한다. API가 새 컬럼 `moderator_request_kind`를 조회하므로 SQL을 먼저 적용해야 한다.
3. 열려 있던 브라우저는 새로고침한다. 이전 클라이언트가 보내는 `open_free`는 서버에서 일반 `tick`으로 처리한다.

## 검증

- `npm run test:lounge`: 역할 선택, 요청 종류, 은퇴한 이유(`round_summary`/`free_ending`) 거절, 1:1 무개입, 침묵 조건, 일정 발언 3회.
- `node scripts/lounge-light-moderation-sql-check.mjs`: 격리 PostgreSQL에서 3명·2명·1:1 흐름, 침묵 1회 제한, 요청 종류, 음성 호출, 방장 권한, 이전 세션 복구, 재실행과 권한.
- `LOUNGE_CDP_PORT=9258 node scripts/lounge-session-browser-check.mjs` (Vite 5191): 차례 뒤 정리 없이 자유 대화, 카드 전환 때 AI 무발화, 마무리 차례, 도움 메뉴.

실제 AI 발화 품질, 끼어들기 감도, 2·4·6명 방의 체감은 실사용으로 확인해야 한다. 확인할 지표는 자연스러운 대화 중 AI 자동 발언 0회, AI 발화 시간 비중 10% 이하, 끼어들기 오작동 빈도다.
