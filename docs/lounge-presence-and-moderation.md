# 앱 전환 중 참가 상태와 사회자 진행

> 2026-10-06: 아래의 주제별 사회자 정리(`summarizing`)와 자유 대화 종료 예고는 [가벼운 진행](lounge-light-moderation.md)에서 없앴다. 참가 상태 유지 규칙은 그대로다.

모바일 브라우저가 다른 앱 사용 중 타이머·음성 연결을 중단해도 라운지 참가 상태와 자리를 유지한다. 명시적인 나가기, 방장의 종료, 기존 방 만료와 대화 마무리는 그대로 적용한다. 비활성 사용자에게 새 참가자가 들어왔다고 자동 퇴장을 적용하지 않으며, 방장 갱신이 90초 끊겼다는 이유로 방을 종료하지 않는다.

참가자 프로필과 인원은 DB의 `active` 명단을 기준으로 표시한다. 음성 연결이 잠시 끊기면 마이크는 꺼진 상태로 표시하고 마지막 프로필을 유지한다. 화면 복귀·페이지 복원·네트워크 복구 시 참가 상태를 갱신하고 방을 확인한 뒤 음성을 다시 연결한다. 연결이 복구되면 사용자가 켜 두었던 마이크만 복원하며, 직접 끈 마이크는 켜지 않는다. 운영체제가 중단한 백그라운드 음성 송수신을 웹 페이지에서 강제 유지하는 기능은 아니다.

사회자는 처음에 사전 자료와 방 소개를 바탕으로 주제의 배경, 방을 만든 계기, 나누고 싶은 이야기와 대화 목적을 설명한다. 이후 세션의 시작에서는 그 순서의 목적과 질문을 소개한다. 패스 안내는 첫 인사에만 유지한다.

주제별 기본 발언이 끝나면 `summarizing` 상태로 이동한다. 사회자는 해당 세션의 발언을 사용자 ID로 구분해 정리하고 실제 관점 차이·공통점·미해결 질문으로 발언자들을 연결한다. 최근 24개 메시지에서 빠진 앞선 발언도 별도로 조회한다. 다른 세션에서 늦게 도착한 전사는 제외하며, 발언하지 않은 사람의 생각은 만들지 않는다. 정리를 저장해도 참가자 마이크를 열지 않고, 사회자 음성 재생을 마친 뒤 방장이 `open_free`로 같은 차례를 확인하면 자유 대화를 열고 최소 60초를 보장한다. 음성이 실패한 경우에는 저장된 정리 글로 이어간다. 사람의 매 발언마다 AI가 답하는 방식은 유지하지 않는다.

자유 대화가 끝나기 30초 전에 다음 이야기로 넘어간다는 예고를 한 번 한다. 방장이 ‘다음 이야기로’를 눌러도 곧바로 넘기지 않고 30초의 마무리 시간을 둔다. 진행 중인 발언·전사·사회자 음성을 끊지 않는다. AI 연결 실패로 대화가 계속 막히지 않도록 정리는 90초, 종료 예고는 예정 시각에서 60초가 지나면 진행을 복구한다. 중복 요청은 DB 티켓과 세션별 완료 표시로 막는다.

## 적용

`supabase/migrations/20261005000000_voice_lounge_presence_and_moderation.sql`은 `20261004040000_voice_lounge_round_then_free.sql` 이후에 적용한다. 기존 차례와 이미 열린 자유 대화를 유지하며 재실행해도 종료 예정 시각을 초기화하지 않는다. 클라이언트와 API를 함께 배포한 뒤 기존 브라우저를 새로고침한다.

## 검증

- `scripts/lounge-presence-moderation-sql-check.mjs`: 격리 PostgreSQL에서 비활성 참가자의 자리·순서·인원 유지, 방장 비활성 상태, 직접 나가기, 요약과 종료 예고의 중복·권한, 실패 복구와 SQL 재실행 검증.
- 라운지 API 테스트: 비활성 참가자 맥락 유지, 전체 세션 발언과 사용자 구분, 이전 세션의 지연 전사 제외, 종료 예고와 분야별 다음 주제 검증.
- 세션 브라우저 검사: 프로필 유지, 화면 복귀 재연결, 마이크 선택 복원, 정리 후 자유 대화, 종료 예고와 기존 전사·발언 종료·대화 보호 검증.

브라우저 검사는 합성 오디오와 모의 API를 사용하며 실제 참가자의 방이나 유료 AI를 호출하지 않는다. 실제 휴대폰의 앱 전환과 AI 발언 품질은 배포 후 실사용으로 확인한다.
