# 라운지 대화 친구와 다시 만나기

기획일: 2026-10-03. 아래 기능은 제안이며 아직 구현하지 않았다. 기존 라운지의 주제·음성·프로필·발언 순서 기능을 바탕으로 설계한다.

## 목표와 첫 출시 범위

좋았던 대화가 다음 만남으로 이어지게 한다. 처음 만나는 사람에 대한 부담을 줄이면서, 상대에게 연락처나 얼굴 공개를 요구하지 않고 관계를 이어갈 수 있게 한다. 첫 출시는 **함께 대화한 사람 → 상호 선택 → 대화 친구 → 다음 라운지 초대**에 집중한다.

친구는 서로 동의한 관계다. 한쪽이 관심을 표시한 사실, 상대가 선택하지 않은 사실, 관심을 받은 숫자는 공개하지 않는다. 낯선 사람 전체를 검색하는 화면이나 팔로워 순위는 첫 출시 범위에 넣지 않는다. 기존 문서 `lounge-connections-plan.md`의 만남·사진 공개 아이디어 중, 이 기획에서는 관심사 기반 친구와 재대화 경험을 우선한다.

## 사용자 흐름

1. **대화 중 참가자 프로필:** 사진/캐리커처를 누르면 닉네임, 본인이 고른 관심사, 한 줄 소개, 함께한 대화의 주제를 보여 준다. `다시 이야기하고 싶어요`를 선택할 수 있으며 선택은 본인에게만 보인다. 다시 눌러 취소할 수 있다. AI 진행자와 본인은 선택할 수 없다.
2. **대화가 끝난 뒤:** `다시 이야기하고 싶은 분이 있었나요?` 화면에 실제 함께 참여한 사람을 표시한다. 여러 명을 선택하거나 `오늘은 여기까지`로 넘어갈 수 있다. 먼저 나간 사람도 종료 화면을 확인할 수 있어야 한다. 기존 방장 퇴장에 따른 방 종료와 연결 UI는 별도로 처리한다.
3. **상호 선택:** 두 사람이 유효한 기간 안에 선택하면 `서로 다시 이야기하고 싶어 했어요. 대화 친구가 되었어요.`를 두 사람에게 알린다. 선택 버튼 아래에 `서로 선택하면 대화 친구로 연결돼요`를 미리 안내해 자동 연결에 대한 동의를 분명히 한다. 한쪽만 선택한 상태에서는 상대에게 알림을 보내지 않는다.
4. **다시 만나기:** `내 대화 친구`에서 주제를 정해 라운지에 초대한다. 상대가 수락하면 서버에서 정원과 참가 권한을 확인해 입장한다. 초대는 상대의 현재 대화를 강제로 끊거나 마이크를 켜지 않는다.

상호 선택은 첫 출시의 유일한 친구 연결 방식으로 둔다. 일방적인 친구 요청은 이후 필요성이 확인되면 수신 설정과 함께 검토한다.

## 화면 구성

| 위치 | 보여 줄 내용 | 주요 동작 |
| --- | --- | --- |
| 참가자 프로필 | 닉네임, 캐리커처, 관심사, 한 줄 소개 | 다시 이야기하고 싶어요 / 차단 / 신고 |
| 종료 화면 | 함께 대화한 사람, 오늘의 주제 | 관심 선택 / 건너뛰기 |
| 메인 상단 `대화 친구` | 내 친구, 받은 라운지 초대 | 친구 목록 / 초대 확인 |
| 친구 목록 | 닉네임, 아바타, 함께 나눈 관심사 | 프로필 보기 / 라운지 초대 / 친구 해제 |
| 초대 알림 | 보낸 친구, 직접 입력한 주제, 시간, 예상 인원 | 수락 / 나중에 / 거절 |

접속 중 여부는 기본 비공개로 둔다. 설정에서 `친구에게 지금 초대 가능 표시`를 켠 사람에게만 상태를 표시한다. 친구가 참여 중인 비공개 방, 실제 접속 시각, 친구의 친구 목록은 공개하지 않는다. 공개 방의 외부 링크는 친구 전용 초대와 구분한다.

## 부담을 줄이는 연결 원칙

- **가입 회원에게 지속적인 친구 관계 제공:** 게스트는 음성 대화에 참여할 수 있지만, 친구 연결을 저장하려면 계정을 만들도록 안내한다. 가입으로 계정 ID가 바뀌는 경로에서는 게스트의 관심 선택을 임의로 다른 계정에 넘기지 않는다. 계정 연결이 서버에서 확인된 경우에만 이어받는다.
- **원본 사진은 별도 기능:** 캐리커처로 친구가 되어도 원본 사진, 이메일, 연락처를 공개하지 않는다. 향후 사진 공개 기능을 만들 경우 공개 범위·기간·철회 방법을 따로 선택하게 한다. 상호 선택을 사진 공개 동의로 해석하지 않는다.
- **연락은 초대부터:** 첫 출시에는 자유로운 개인 메시지와 파일/링크 전송을 추가하지 않는다. 주제와 시간을 담은 정형 라운지 초대로 재대화를 시작한다. 개인 메시지는 수신 거부·차단·신고 운영이 준비된 뒤 검토한다.
- **빈번한 초대 억제:** 동일 상대에게 미응답 초대를 겹쳐 보내지 못하게 하고, 기본 실험값으로 같은 사람에게 하루 3회까지 초대를 허용한다. 상대가 거절한 초대는 같은 방으로 다시 보내지 못하게 한다. 이 값은 초기 운영 결과로 조정한다.
- **해제와 차단:** 친구 해제는 관계와 미응답 초대를 종료하고 기존 상호 관심도 지운다. 차단하면 관심 선택·친구 연결·초대가 모두 막힌다. 상대에게 차단 사실을 별도 알림으로 전달하지 않는다. 다시 연결하려면 차단 해제와 양쪽의 새 선택이 필요하다.

차단 상태는 화면뿐 아니라 초대 RPC, 방 입장 RPC, LiveKit 토큰 발급에서도 검증한다. 공개 방에서도 차단한 두 사람이 새로 같은 방에 들어가지 않도록 처리하고, 정원·참가 불가 안내에서 차단한 사람의 신원을 노출하지 않는다. 이미 같은 방에 있는 사람을 차단하면 우선 해당 음성을 즉시 듣지 않도록 하고 퇴장/신고 선택을 제공한다. 원격 음성 송출 차단이나 강제 퇴장은 서버의 LiveKit 제어로 따로 구현해야 한다.

## 서버 데이터와 권한

다음은 개념 설계다. 실제 SQL은 구현 때 기존 계정·회원 테이블과 RLS를 확인한 뒤 작성한다.

| 데이터 | 목적 | 접근 범위 |
| --- | --- | --- |
| `lounge_connection_profiles` | 관심사, 한 줄 소개, 초대 수신 설정 | 본인 및 승인된 프로필 조회 경로 |
| `lounge_shared_sessions` | 같은 방에 참여했다는 최소한의 근거 | 서버 내부 검증용 |
| `lounge_connection_intents` | 상대를 다시 만나고 싶은 선택, 만료 시각 | 본인 선택만 조회 |
| `lounge_connections` | 상호 동의한 친구 관계 | 두 당사자만 조회 |
| `lounge_room_invites` | 친구의 방 초대와 수락/거절/만료 상태 | 보낸 사람과 받은 사람 |
| `lounge_user_blocks` | 차단 관계 | 차단한 본인만 조회 |
| `lounge_reports` | 문제 상황과 운영 처리 | 신고자와 운영자 |

두 사용자 ID를 정렬한 단일 쌍을 키로 사용해 친구 관계가 중복되지 않게 한다. 관심 저장·상호 연결·해제·차단은 RPC로만 변경하고, 같은 사용자 쌍에 대한 트랜잭션 잠금으로 동시에 선택하거나 차단해도 상태가 엇갈리지 않게 한다. 클라이언트가 보낸 상대 ID만으로 관계를 만들지 않는다.

연결 자격은 가입 회원이고, 서버에서 확인한 최근 공동 참여 이력이 있으며, 양방향 차단이 없는 경우다. 첫 실험에서는 공동 참여 이력 30일, 관심 선택 유효기간 7일을 기본값으로 둔다. 단순히 방 목록을 보거나 초대 링크를 가진 사실은 공동 참여로 인정하지 않는다. 양쪽이 실제 방 멤버였다는 기록을 사용하고, 필요한 경우 서버의 음성 연결 이력과 함께 검증한다.

현재 방과 발언 기록은 만료 후 정리 대상이다. 친구의 재대화 이력을 보존하려면 방 삭제 전에 **당사자 ID·공동 참여 시각·선택적으로 짧은 주제**만 별도 기록으로 옮기는 경로가 필요하다. 원본 음성이나 대화 전문을 친구 프로필에 복사하지 않는다. 관심 만료, 친구 해제, 차단, 계정 삭제에 따른 데이터 정리 작업도 함께 구현한다. 기존 정리 함수의 정기 실행은 별도 설정 여부를 확인해야 한다.

수락한 초대는 곧바로 영구적인 방 접근 권한이 되지 않는다. 수락 시점과 토큰 발급 시점 모두 방 상태·정원·친구/차단 상태를 검증한다. 친구 전용 방을 추가하려면 현재 공개 방 조회, 입장 함수, 초대 링크의 접근 규칙을 함께 확장해야 한다.

## 구현 순서와 검증

**1차 — 대화 친구:** 등록 회원 프로필, 차단/신고/수신 제어, 공동 참여 기록, 비공개 관심 선택, 상호 연결, 친구 목록, 해제. 종료 화면 접근과 계정 삭제까지 함께 구현한다.

**2차 — 다음 라운지 초대:** 알림함, 초대 수락/거절/만료, 공개 방 초대의 정원 검증, 중복·빈도 제한. 친구 전용 방은 접근 권한을 별도로 구현한 뒤 제공한다.

**3차 — 반복 모임:** 다음 만남 일정, 관심 주제별 작은 모임, 참가자 동의를 받은 재초대. 사진 공개와 개인 메시지는 수요와 운영 여력이 확인되면 독립적으로 검토한다.

서버 검증에서는 동시 상호 선택, 취소와 수락의 경합, 만료된 관심, 차단 직후 초대 수락, 친구 해제 후 토큰 발급, 꽉 찬 방, 계정 삭제를 확인한다. 다른 사람의 일방 관심·차단·초대·친구 목록을 읽을 수 없는지도 확인한다.

성과는 친구 수보다 **상호 연결 후 실제 재대화**로 판단한다. 종료 화면 선택률, 상호 연결률, 초대 수락률, 7일 안의 재대화율, 차단/신고와 초대 수신 거부 비율을 함께 본다. 가입자별 성격·호감·궁합 점수는 만들지 않는다.

## 제품 문구

- 관심 선택: `다시 이야기하고 싶어요`
- 선택 안내: `서로 선택하면 대화 친구로 연결돼요. 한쪽만 선택한 경우에는 상대에게 알려지지 않아요.`
- 연결 완료: `좋았던 대화를, 다음에도. 서로 대화 친구가 되었어요.`
- 초대: `다음에는 이 주제로 이야기해 볼까요?`
- 다음 만남: `새로운 사람을 만나도 좋고, 편했던 사람과 다시 만나도 좋아요.`
