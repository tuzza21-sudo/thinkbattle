# 사석 광고 에이전트: 별도 프로젝트 시작 문서

이 문서는 사석 사이트 저장소(`thinkbattle`)가 광고 에이전트에게 **이미 넘겨 주는 것**과, 별도 프로젝트에서 **만들어야 하는 것**을 정리한다. 에이전트는 이 저장소와 분리된 새 폴더/저장소에서 만든다.

## 1. 왜 분리하나
- 광고 계정 토큰은 돈을 쓸 수 있는 권한이다. 사용자가 접속하는 사이트의 서버 환경변수에 함께 두지 않는다.
- 릴스 영상 합성은 오래 걸려 Vercel 함수(최대 60초)에 맞지 않는다.
- 에이전트를 고치다 사이트 배포가 깨지는 일을 막는다.

## 2. 사이트가 이미 하는 일 (이 저장소, 배포 완료)
| 기능 | 위치 | 비고 |

| 메타 픽셀(데이터세트 `2860857600965753`)과 화면별 `PageView` | `src/lib/metaPixel.ts` | "추적 안 함"/GPC 신호는 측정하지 않음 |

## 3. 에이전트가 만들 것
1. **소재 생성**: `assets.json`의 캐릭터 사진, 장소 배경, 대표 한마디로 이미지(1:1, 4:5)와 릴스(9:16, 15~30초)를 만든다.
   - 릴스 구성 예: 장소 배경 + 캐릭터 사진 + 대사 자막 + 캐릭터 음성(TTS) + 사이트 화면 예시.
   - 모든 소재에 "AI로 만든 가상의 인물" 표시와 "화면 예시" 표시를 넣는다.
2. **광고 등록**: 메타 마케팅 API로 캠페인 → 광고 세트 → 광고를 만든다. 처음에는 **일시중지 상태로 생성**한다.
3. **성과 수집**: 메타 인사이트(노출, 클릭, 비용)와 `ad_funnel_report`(가입, 말한 사람, 다른 날 돌아온 사람)를 합쳐 캠페인별 비용 대비 성과를 계산한다.
4. **운영 제안**: 성과가 나쁜 광고는 중지, 좋은 광고는 증액을 **제안**한다. 실행은 사람이 승인한다.

## 4. 광고 링크 규칙 (성과를 캠페인별로 읽으려면 반드시 지킨다)
```
https://saseok.kr/lounge/about?utm_source=meta&utm_medium=paid&utm_campaign=<캠페인>&utm_content=<소재ID>
https://saseok.kr/lounge/characters/<캐릭터id>?utm_source=meta&utm_medium=paid&utm_campaign=<캠페인>&utm_content=<소재ID>
```
- `utm_campaign`: `<캐릭터id>_<yyyymm>_<목적>` 처럼 일정한 규칙으로 쓴다(영문 소문자, 숫자, `_`, `-`).
- 값은 80자 이내, 영문·숫자·한글·`_.-:` 만 저장된다.
- 메타가 붙이는 `fbclid`는 자동으로 인식해 "메타 광고에서 온 방문"으로 기록된다.

## 5. 퍼널 읽기
```
POST {SUPABASE_URL}/rest/v1/rpc/ad_funnel_report
apikey / Authorization: Bearer <서버 역할 키>
{ "p_from": "2026-10-15", "p_to": "2026-10-21" }
→ [{ day, source, medium, campaign, signups, spoke, returned }]
```
- `signups`: 그날 가입한 회원 / `spoke`: 그중 한 번이라도 말한 사람 / `returned`: 두 날 이상 말한 사람.
- 서버 역할 키는 모든 사용자 데이터에 접근하는 강한 권한이다. 에이전트에는 이 함수만 호출하는 전용 경로(별도 함수나 제한된 키)를 만들어 쓰는 것을 권한다.

## 6. 안전 장치 (처음부터 넣는다)
- **하루 예산 상한**과 **월 예산 상한**을 설정 파일에 두고, 넘으면 모든 광고를 일시중지한다.
- **사람 승인**: 소재 게시, 예산 증액, 새 캠페인은 승인 후에만 실행한다. 승인 기록을 남긴다.
- **정책 점검**: 문구에 "외로우신가요?"처럼 보는 사람의 상태를 짐작하는 표현, 상담·치유 약속, 연애 중심 표현이 있으면 등록하지 않는다. 데이팅으로 분류되면 사전 승인이 필요하다.
- **AI 생성 표시**: 이미지와 영상에 AI 생성 표시를 한다(메타의 AI 라벨 정책 확인).
- **연령**: 18세 이상만 대상으로 한다.
- 토큰은 환경변수나 비밀 저장소에만 두고 저장소에 올리지 않는다.

## 8. 권하는 개발 순서
1. 소재 생성만(이미지 → 릴스) 만들어 손으로 광고를 올려 본다.
2. 수동 캠페인으로 데이터가 쌓이는지(`ad_funnel_report`, 이벤트 관리자) 확인한다.
3. 광고 등록을 API로 자동화하되 일시중지 상태 + 승인 후 게시로 둔다.
4. 성과 수집과 일일 리포트를 붙인다.
5. 충분한 데이터가 쌓인 뒤 제한된 범위의 자동 최적화(중지, 소액 증액)를 연다.

## 9. 폴더 제안
```
saseok-ad-agent/
  config/            예산 상한, 승인 규칙, 금지 문구
  creatives/         소재 생성(이미지, 릴스)
  meta/              마케팅 API 클라이언트
  reports/           인사이트 + 퍼널 합치기, 일일 리포트
  approvals/         승인 대기열과 기록
  .env               META_SYSTEM_USER_TOKEN, META_AD_ACCOUNT_ID, SUPABASE_URL 등 (저장소에 올리지 않음)
```
