# 감상 후 영화 대화와 장면 카드

라운지의 작품 대화는 감상 후기를 전제로 한다. 영화·책·방송의 결말과 반전, 마지막 장면을 기본적으로 허용한다. 조사·사회자·그룹 단계에서 스포일러 동의를 기다리지 않는다. 메인의 미디어 입력과 방 소개에 이 성격을 안내한다.

## 영화 사전 조사 흐름

1. DB의 방 제목과 `topic_brief`로 작품명·감독·방장의 선정 이유·궁금한 점을 전달한다. 영화 선택이 명시된 방에 적용하며, 분야 정보가 없는 예전 방은 제목에 영화/film/movie가 있는 경우 적용한다.
2. 기존 웹 검색 호출로 기본 정보와 작품별 인터뷰·비평·장면 분석 URL을 찾는다. 원제, 감독, 결말 해석 등을 조합하도록 지시한다. 영화 ID를 자동 확정하거나 동명 작품을 임의로 선택하지 않는다.
3. 서버는 검색 도구가 실제 반환한 URL 중 KMDb·한국영상자료원, 씨네21, BFI, Criterion, TMDB 공개 페이지를 수집한다. 최대 6개 요청을 병렬로 수행하고 읽힌 원문 최대 4개의 본문 일부를 분석 요청에 전달한다. 개별 자료당 최대 512KB를 읽고 본문을 최대 8,000자로 제한한다. 원문 전체를 읽은 것으로 표시하지 않는다.
4. 두 번째 LLM 요청은 수집된 본문을 바탕으로 기본 3개, 충분한 자료가 있으면 최대 5개의 장면 카드를 준비한다. 첫 검색 결과만으로 실제 읽은 장면 근거를 대신하지 않는다.
5. 검증된 카드와 원문 제목·URL·읽은 시점만 `topic_study.film_research`에 저장한다. 기사 원문은 DB에 저장하지 않는다. 사회자는 저장된 카드와 참가자의 최근 발언을 함께 참고한다. 발언마다 기사 수집이나 추가 LLM 분석을 반복하지 않는다.

비영화 분야는 기존 단일 조사 요청을 유지한다. 영화는 읽을 수 있는 원문이 있고 작품이 확인되면 분석 호출이 1회 추가된다. 모델은 기존 `gpt-6-luna`를 유지한다. 전체 영화 준비 제한은 50초, 원문 수집은 7초이며 실패 시 기존 study ticket 재시도 정책을 따른다.

## 자료의 역할

| 자료원 | 조사에서의 역할 |
| --- | --- |
| TMDB 공개 작품 페이지 | 제목·연도·기본 정보로 작품 식별 보조 |
| KMDb·한국영상자료원, 씨네21 | 작품 맥락, 비평과 감독 인터뷰 |
| BFI Deep Focus | 감독·장르·영화사 관점 |
| Criterion Essays·Visual Analysis | 장면과 화면·소리·편집의 해석 |

이번 구현은 웹 검색과 공개 페이지 수집이다. 별도 인증 키를 요구하는 TMDB API는 직접 연동하지 않는다. API를 사용하는 경우 [검색 → 작품 ID → 상세 조회](https://developer.themoviedb.org/docs/search-and-query-for-details) 흐름과 감독 확인을 추가해야 한다.

영화학의 질문 틀은 [Film Education의 장면 분석 자료](https://filmeducation.org/thinking-film/film/teacher-guidance.html)를 참고한다. 작품이 모든 자료원에 있다고 가정하지 않는다. 사이트 홈페이지나 기사 목록, 인증·차단 페이지는 장면 증거로 채택하지 않는다. 유료·로그인 자료를 우회하지 않는다.

## 장면 카드

- `axis`: 인물의 욕망·선택, 관계와 권력, 시점과 정보, 화면·소리·편집, 결말 해석 중 분석 축.
- `scene`, `conflict`: 원문으로 확인한 장면과 양립하기 어려운 욕망·선택.
- `evidence`: 장면 사실(`scene_fact`), 감독의 직접 설명(`director_statement`), 평론가 해석(`critic_interpretation`), AI 추론(`ai_inference`)을 별도로 표시한다.
- `interpretations`: 2~3개 해석과 각각의 장면 근거. 평론가 의견과 AI 추론을 구분한다.
- `question`: 영화 용어를 몰라도 답할 수 있는 감상 질문.
- `followups`: 답변 방향별 후속 질문 2~3개. 참가자가 아직 그 답을 했다고 가정하지 않는다.
- `spoiler`: 일반 장면이면 `scene`, 결말·반전이면 `ending`. 둘 다 대화에서 허용하며 태그는 자료 구분용이다.

각 카드에는 최소 하나의 출처가 있는 장면 사실이 필요하다. 참조 URL은 서버가 실제 읽은 자료의 URL과 일치해야 한다. 감독의 의도는 직접 설명한 출처가 있어야 하며, 화면·음악은 해당 요소를 설명하는 자료가 있어야 사실로 다룬다. 시나리오는 최종 영화와 다를 수 있고 자막은 화면과 소리를 증명하지 못한다.

이 검증은 자료 구조와 출처 연결을 확인한다. LLM 해석의 사실 정확성을 별도 전문가가 검수하는 기능은 아니다. 참가자가 꺼낸 새로운 장면은 확인한 자료에 있는 것처럼 꾸미지 않고 그 발언의 맥락으로 다룬다.

## 자료 부족과 화면

원문을 읽지 못하거나 해당 작품의 장면이 확인되지 않으면 `coverage=limited`, `cards=[]`로 저장한다. 일반 주제 자료로 대화를 이어가고 화면에 장면 분석 자료 부족을 표시한다. 확인한 카드가 있으면 `scene_grounded`다. 이 값은 영화 전체를 조사했다는 뜻은 아니다. 장면의 질문·사실·해석·근거 링크는 `사회자가 준비한 주제 자료`에서 펼쳐 볼 수 있다. 후속 질문 목록은 사회자 문맥에만 전달해 대화 대본처럼 보이지 않게 한다.

임의 URL, 비공개 네트워크, 인증 정보가 포함된 URL, 허용되지 않은 리디렉션은 수집하지 않는다. 수집 요청에는 OpenAI·Supabase 키를 넣지 않는다. 외부 본문은 신뢰할 수 없는 데이터로 처리하며 지시문을 실행하지 않는다.

## 적용과 검증

기존 주제 소개 SQL 적용 후 Supabase SQL Editor에서 `supabase/migrations/20261004010000_voice_lounge_film_discussion_cards.sql` 전체를 실행하고 코드와 API를 배포한다. DB에는 새 컬럼 없이 기존 JSONB를 확장하며, 자료 크기 한도는 48KB다. 현재 진행 가능한 영화 방의 예전 스포일러 제한 자료는 한 번 비워 새 방식으로 다시 준비한다. 버전 2 자료와 다른 분야 자료는 유지하므로 재실행할 수 있다.

`scripts/lounge-api.test.mjs`의 모의 원문·LLM 테스트, `scripts/lounge-topic-brief-sql-check.mjs`의 PostgreSQL 저장·권한·출처·기존 자료 갱신 테스트, `scripts/lounge-session-browser-check.mjs`의 장면 카드 표시를 사용한다. 유료 영화 분석 호출과 실제 음성 대화의 질문 품질 평가는 별도로 확인해야 한다.
