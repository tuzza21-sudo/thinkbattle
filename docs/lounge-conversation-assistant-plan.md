# 1:1 대화 개선과 그룹 AI 도우미 기획

2026-10-06. 아래의 ‘반영한 수정’은 이번 코드 변경이고, 그룹 AI 도우미 전환은 구현을 위한 제안이다. 배포와 실제 모바일 기기의 청취 확인은 별도로 필요하다.

## 반영한 수정

- AI 음성을 로컬 재생과 LiveKit 방송으로 나누기 전에 2배(+6 dB) 증폭한다. 큰 소리는 컴프레서로 눌러 증폭에 따른 왜곡을 줄인다. PCM 스트리밍과 MP3 재생에 같은 처리를 적용하므로 방장과 다른 참가자 모두 적용된다. 사람의 마이크는 이 증폭 경로를 거치지 않는다.
- 모바일 소리 켜기는 Web Audio 재개와 LiveKit 오디오 재생의 성공을 함께 확인한다. 한 경로가 차단되었는데 준비 완료로 표시하던 경쟁 상황을 막는다. 원격 재생 요소는 최대 음량과 인라인 재생 속성을 명시한다.
- 1:1은 첫 인사부터 보통 1~2문장·140자 이내를 지시한다. 자세한 설명을 직접 요청했을 때만 3~4문장·300자까지 허용한다. 길이는 모델 지시이며 문장 중간을 강제로 잘라 적용하지 않는다.
- 1:1 첫 인사는 가벼운 인사와 주제에 맞는 질문 하나로 시작한다. 자료·대화 목적·발언 순서·패스를 설명하지 않는다. 이어지는 답변도 발표 말투와 공감→분석→조언→질문의 반복을 피하고, 상대의 이야기에 짧게 답한다. 질문으로 끝내는 것도 강제하지 않는다.

예: “이 방에서는 영화의 배경과 인물의 선택을 살펴보고…” → “반가워요. 그 영화에서 어떤 장면이 계속 생각났어요?” 실제 주제와 상대의 발언에 맞춰 질문한다.

## 현재 ‘사회자 도움’의 동작

모바일과 PC가 같은 기능을 사용한다. 별도의 상담창이나 모바일 전용 기능은 아니다.

1. 그룹 방의 모든 참가자가 버튼을 누르면 `request_voice_lounge_moderator` RPC가 요청 시각과 요청자를 방에 저장한다. 활성 방의 참가 권한과 발언 제한 상태를 확인한다.
2. 방장 화면이 요청을 확인한다. 현재 발언·전사·AI 음성이 진행 중이면 기다리고, 요청 간격과 세션 상태가 허용할 때 `reason=requested`로 AI를 호출한다.
3. AI는 주제 자료·최근 대화·기억을 참고해 답한다. 방장 브라우저가 합성 음성을 LiveKit으로 방송하고, 답변은 공용 대화 기록에 남는다.
4. 완료한 요청은 서버에서 해제한다. 처리 중 들어온 새 요청은 남겨 둔다. 현재 버튼은 ‘도움이 필요하다’는 신호만 보내며 어떤 종류의 도움인지는 보내지 않는다.

“사회자, 어떻게 생각해?”처럼 AI를 직접 부르는 전사도 요청을 등록할 수 있다. 정해진 호칭·요청 표현을 찾는 방식이므로 모든 자연어 호출을 알아듣는 것은 아니다. 순서 발언 중에는 요청이 저장되어도 허용된 단계까지 기다릴 수 있다. 방장 브라우저가 중단되면 음성 생성·방송도 지연될 수 있다.

1:1에서는 버튼 이름이 ‘화제 하나 던져줘’이며 방장 화면에서 바로 같은 `requested` 응답을 요청한다. 현재는 도움 유형을 명시하지 않아 화제 제안보다 직전 질문에 대한 응답이 나올 수도 있다.

## 그룹 기본 경험 제안

사람이 두 명 이상인 방의 기본값을 **자유 대화 + 필요할 때 AI 도움**으로 바꾼다. 기존 순서 발언 프로그램은 방 만들기의 선택 사항으로 둔다. 시스템은 참가 상태와 대화 보호를 관리하고, AI는 대화의 중심을 맡지 않는다.

- 시작: “편하게 이야기 나눠요. 필요하면 저를 불러 주세요.”처럼 한두 문장으로 인사한다. 말문이 없으면 주제에 맞는 질문 하나만 건넨다.
- 진행: 대화가 오가는 동안에는 칭찬·해설·요약·참가자 지목을 추가하지 않는다. 시간에 맞춰 단계를 넘기거나 모든 사람에게 답변을 요구하지 않는다.
- 도움: 어색한 침묵이나 명시적인 요청 때만 분위기를 풀 한마디, 지금 필요한 질문 하나, 이어갈 화제 하나 중 하나를 선택한다. 보통 한두 문장·120자 이내를 지시한다. 직접 설명을 요청하면 짧게 답한다.
- 마무리: 종료 확인은 화면으로 처리한다. 음성 요약은 요청할 때만 제공한다. 기존 순서 발언 모드는 기존의 정리와 전환을 유지한다.

예: “두 분의 의견을 종합하면…”보다 “같은 장면을 꽤 다르게 보셨네요. 그 선택을 이해했던 순간도 있었어요?”를 한 번 건네고 사람끼리 답하도록 기다린다. 진지한 고민에는 농담을 넣지 않는다. 참가자의 감정이나 어색함을 사실로 단정하지 않는다.

## 개입 조건 제안

MVP에서는 ‘어색한 분위기’를 감정 판정으로 알아내지 않고, 발언 활동과 사용자의 요청으로 판단한다. 침묵은 생각할 시간일 수도 있으므로 자동 참여를 끌 수 있어야 한다.

| 조건 | 제안 동작 |
| --- | --- |
| 사람이 말하거나 전사 대기 중 | AI 요청과 재생을 보류한다. |
| 사람이 서로 대화 중 | 자동 참여하지 않는다. |
| ‘AI 도움받기’ 버튼 또는 직접 호출 | 명시적으로 요청한 유형에 맞춰 짧게 돕는다. 사람이 말하는 중이면 요청 상태만 표시한다. |
| 마지막 사람 음성·글·전사 이후 30초 침묵 + AI 종료 후 120초 경과 | ‘필요할 때 참여’ 설정일 때만 짧은 연결 질문을 한 번 제안한다. |
| 자동 참여 뒤 사람 반응이 없음 | 같은 침묵에서 두 번째로 말을 걸지 않는다. 새로운 사람 발언이나 명시적인 요청이 있어야 다시 활성화한다. |
| AI 생성 중 사람이 대화를 재개 | 자동 참여 요청을 취소하고 음성을 시작하지 않는다. 직접 도움 요청은 잠시 보류하되 만료 후 안내한다. |
| AI가 말하는 중 사람이 발언 | 사람의 발언을 우선해 남은 AI 음성을 중단한다. |
| 앱 전환으로 연결 인원이 일시적으로 감소 | 서버의 활성 멤버와 방 모드를 기준으로 그룹 역할을 유지한다. 한 명만 연결됐다는 이유로 매 발언 응답 모드로 바꾸지 않는다. |

숫자는 초기 실험값이다. 현재 자유 대화는 30초 침묵·최근 AI 요청 후 90초를 사용한다. 변경 시 클라이언트뿐 아니라 서버 RPC에도 같은 규칙을 적용해야 한다. 명시적인 도움 요청에는 자동 참여용 120초 제한을 적용하지 않고 별도의 짧은 중복 방지 간격을 둔다.

## 화면과 데이터

- ‘사회자 도움’ → ‘AI 도움받기’. 클릭하면 ‘말문 열어줘 / 질문 하나 / 다른 화제 / 지금 이야기 정리’를 선택한다. 선택한 요청은 방에 공유한다. ‘말문 열어줘’는 빠른 기본 동작으로 제공한다.
- AI 참여 설정은 ‘필요할 때 참여’와 ‘부를 때만 참여’ 두 가지로 제공한다. 그룹 기본값은 전자이며 설정 변경은 방장이 하고 모두에게 현재 설정을 표시한다.
- AI 표시를 ‘AI 도우미 · 필요할 때 불러 주세요’로 바꾼다. 요청 상태는 ‘요청했어요. 이야기가 잠깐 멈추면 도와드릴게요.’처럼 알린다. 거절·만료·오류는 완료로 표시하지 않는다.
- 방 데이터에 `conversation_mode`(companion / assistant / guided)와 `assistant_participation`(on_pause / on_request)을 추가한다. 기존 방은 capacity와 guided_session에 따라 매핑한다. 새 그룹 방은 assistant를 기본값으로 만든다.
- 요청 데이터에 `request_id`, `request_kind`, `requested_by`, `requested_at`, `status`, `expires_at`을 저장한다. 한 번에 한 요청을 처리하며 같은 요청 ID의 중복 생성·방송을 막는다. LLM 문맥에 도움 유형과 요청자의 최근 발언을 전달한다.
- 서버 claim/finish에 방 모드, 개입 이유, 세션 상태와 요청 ID를 확인한다. 자동 참여는 `pause_id`와 `last_auto_pause_id`로 같은 침묵의 반복을 막는다. 마지막 발언 활동과 AI 재생 종료 시각은 방장이 보고하되 서버에서 권한·시각 범위를 검증한다.

## 구현 순서와 제약

1. 모드 마이그레이션과 생성 RPC, UI 선택을 추가한다. 신규 assistant 방은 강제 순서·세션 진행 없이 마이크를 열고 바로 대화한다. 기존 guided 방의 진행은 보존한다.
2. `nextLoungeHostReason`과 `LoungePage`에 모드·설정·침묵 중 한 번만 참여하는 규칙을 연결한다. `api/lounge.ts`는 companion / assistant / guided별로 길이와 개입 지시를 분리한다. DB claim도 같은 조건을 검증한다.
3. 도움 유형 선택과 요청 상태를 연결한다. 요청 문맥을 전달하고 대화 기록에는 실제로 전달한 AI 발언과 취소 상태를 구분한다.
4. 발언 우선권을 구현한다. 현재 AI 발언 동안 로컬 전사 감지를 막고 있고 AI 방송은 방장 참가자에서 나오므로, 그 참가자의 AI 트랙과 사람의 마이크 활동을 구분해야 한다. 방장 마이크의 VAD와 원격 마이크별 활동을 받아 생성 취소·방송 중단을 처리한다. 재생 도중 취소되면 말한 부분과 전체 생성 글을 같은 완료 발언으로 취급하지 않는다.
5. 서버 AI 참가자로 생성·방송·VAD를 옮기는 후속 작업을 진행한다. 초기 버전은 방장 브라우저 의존을 유지하므로 모바일 백그라운드에서 완전한 연속 동작을 보장할 수 없다.

단순히 프롬프트만 조용하게 바꾸면 현재 단계별 안내·정리 호출과 강제 마이크 차례가 남는다. 기본 방 모드와 서버 호출 조건을 함께 바꾸는 것이 이번 방향의 핵심 구현이다.

## 검증과 품질 기준

- 1:1: 첫 인사에서 배경 강의와 패스 안내가 나오지 않는지, 질문 없이도 짧게 답하는지, 명시적인 설명 요청만 확장하는지 실제 음성으로 평가한다.
- 그룹: 2명·4명·6명에서 자연스럽게 대화할 때 AI 자동 발언 0회, 긴 침묵에서 1회, 반응 없는 같은 침묵에서 재개입 0회인지 확인한다.
- 음성: iPhone Safari와 Android Chrome에서 방장·참가자 각각 확인한다. 이어폰·스피커, 마이크 동시 사용, ‘소리 켜기’, 앱 복귀와 재연결을 포함한다.
- 요청: 동시 클릭, 생성 중 새 발언, 취소 후 늦게 도착한 응답, 제한된 참가자, 방장 이탈·교체, 만료와 API 오류를 확인한다. 같은 요청의 모델 호출과 방송은 각각 한 번이어야 한다.
- 지표: 도움 요청 후 실제 음성 시작 지연, 자동 개입 후 15초 안의 사람 발언 재개율, 사람과 AI의 겹침, 자동 참여 끄기 비율, 음성 준비 오류를 기록한다. AI 발언 시간 비중 10% 이하는 초기 목표이며 실제 사용자 평가와 함께 조정한다.
