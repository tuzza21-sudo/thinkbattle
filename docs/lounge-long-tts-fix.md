# 긴 사회자 발언의 음성 중단 수정

2026-10-04

사회자 텍스트는 기존처럼 최대 600자로 저장하고 읽는다. 기존 음성 요청은 25초의 고정 타임아웃을 응답 본문 수신에도 적용했고, PCM 데이터가 3,000,000바이트를 넘으면 중단했다. 24kHz·16비트·모노 PCM에서는 약 62.5초에 해당하므로 긴 한국어 발언이 이 제한에 걸릴 수 있었다. 브라우저는 전송 오류가 발생하면 이미 받아 재생 예약한 음성도 즉시 정지했다.

`loungeSpeechLimits`는 텍스트 길이에 따라 음성 생성·수신 타임아웃을 30초에서 최대 120초까지 설정한다. PCM 허용량도 글자 수에 맞춘 예상 발화 시간과 여유분을 기준으로 계산하며 최대 240초로 제한한다. 긴 발언을 지원하면서 무제한 음성 수신은 막는다. 실제 제한 초과와 타임아웃에는 각각 `lounge_audio_too_long`, `lounge_audio_timeout`을 전달한다. MP3 응답도 동일한 타임아웃과 사용자 요청 취소 신호를 사용한다.

브라우저는 전송 오류가 나도 이미 받은 정상 PCM 샘플과 마지막 버퍼를 한 번씩 재생한 후 원래 오류를 전달한다. 방 나가기·연결 종료·명시적 재생 중지는 계속 즉시 취소한다. 전송 실패한 나머지 음성을 복구하거나 전체 발언을 다시 읽지는 않는다.

첫 음성을 미리 재생하는 기존 스트리밍 방식, 음성 모델·캐릭터, 발언 텍스트 제한은 유지한다. 전체 음성 수신을 기다리는 단계는 없다. DB 변경도 없다.

## 텍스트만 남는 간헐적 문제 추가 수정

텍스트 저장 후 음성 응답이 도착하는 사이에 사람의 발언·전사 처리가 감지되면 기존 화면은 스트림을 즉시 취소했고, 첫 PCM 패킷을 재생할 때도 같은 조건에서 조용히 반환했다. 저장된 발언은 다음 자동 진행에서 이미 완료한 것으로 판단하므로 이 음성이 다시 재생되지 않는 경로가 있었다.

이제 같은 방·같은 차례가 유효하면 첫 음성 재생 전 잠깐의 발언이나 전사를 최대 8초 기다린다. 조용해지면 받아 둔 음성을 사용한다. 계속 말하는 사람을 끊지는 않으며 대기 시간을 넘으면 `lounge_audio_deferred` 안내를 표시한다. 방 종료, 연결 종료, 발언 제한, 차례 변경 또는 명시적 중지는 기다리지 않고 취소한다. 브라우저 AudioContext는 재생 전에 재개를 시도하고, 실패하면 소리 켜기 안내를 표시한다.

서버는 첫 음성 바이트를 보내기 전의 일시적인 공급자 실패·빈 응답·연결 끊김에서 동일한 텍스트와 목소리로 TTS만 한 번 재시도한다. 답변 생성이나 DB 저장은 반복하지 않는다. 음성이 일부라도 전달됐으면 첫음 중복 방지를 위해 재시도하지 않는다. 인증·크레딧·모델 설정 오류와 요청 제한에도 즉시 재시도하지 않는다. 정상 발언은 기존처럼 TTS 1회이며 복구 시에는 최대 2회 호출로 비용이 늘 수 있다.

추가 검증은 공급자 실패 후 복구, 최대 재시도 횟수, 부분 음성 비반복, 발언·전사와 겹친 음성의 대기 후 재생, 차례 변경 취소, 지속 발언 안내, 대기·재생 중 명시적 중지를 포함한다.

검증에는 모의 API에서 25초 경과를 가상으로 재현하고 4MB PCM이 끝까지 전달되는지 확인하는 테스트, 과도한 PCM 수신 차단, 브라우저에서 시작 전·시작 후 전송 오류 시 버퍼 보존과 즉시 취소 테스트를 사용한다. 실제 유료 TTS 요청이나 운영 서버의 실패 로그를 재현한 것은 아니므로, 다른 공급자·네트워크 오류까지 해결했다고 판단하지 않는다.
