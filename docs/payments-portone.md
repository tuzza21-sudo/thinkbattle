# 결제: 포트원 V2 + KG이니시스 (2026-11-13)

이용권 결제는 포트원 결제모듈 V2(`@portone/browser-sdk`)로 KG이니시스 결제창을 띄운다. 예전의 이니시스 직접 연동(INIStdPay, 모바일 스마트결제, INIAPI 환불)은 없앴다. 결제 완료된 주문이 하나도 없던 때라 옮길 기록도 없었다.

## 흐름

1. 요금제 카드에서 시작 → `POST /api/payments?action=create`. 서버가 가격을 정하고 대기 주문을 만든 뒤 `PortOne.requestPayment`에 넘길 값을 돌려준다(paymentId = 주문번호).
   - PC 이니시스 결제창은 이름·이메일·휴대폰 번호가 필수라서 PC에서는 카드 안에서 휴대폰 번호를 받는다. 번호는 결제창에만 넘기고 저장하지 않는다.
2. PC는 결제창이 닫히면 `/lounge/payment?paymentId=…`로 이동한다. 모바일은 카드사 화면을 거쳐 같은 주소로 돌아온다(실패하면 `code`, `message`가 붙는다).
3. 결과 화면이 `POST ?action=complete`를 부르면 서버가 포트원에서 결제를 조회한다(`GET https://api.portone.io/payments/{id}`). `PAID`이고 금액·통화·상점이 맞을 때만 결제 완료로 기록한다. 금액이 다르거나 기록하지 못한 결제는 포트원 API로 바로 취소한다.
4. 결제마다 `noticeUrls`로 `?action=webhook`을 넘긴다. 결과 화면으로 돌아오지 않은 회원도 웹훅으로 똑같이 처리된다. 포트원 콘솔에서 취소한 결제는 웹훅으로 이용권이 끝난다.
5. 7일 이내 미사용 취소(계정 관리의 이용권)는 `POST /payments/{id}/cancel`로 전액 환불한다.

## 운영 설정 (대표님이 하실 일)

1. 포트원 관리자콘솔 → 결제 연동 → 연동 정보 → 채널 관리 → **채널 추가**
   - 먼저 **테스트 연동**에서 결제대행사 KG이니시스, 결제모듈 **V2**, PG상점아이디 **INIpayTest**로 채널을 만든다. 테스트 결제는 실제로 출금되지만 그날 밤 23:00~23:50에 자동 취소된다. 국민카드는 테스트가 안 된다.
   - 이니시스 계약과 카드사 심사가 끝나면 **실 연동** 채널을 만든다. 필요한 값: MID(MOI로 시작), 웹표준결제 signkey, INIAPI key. 모두 iniweb.inicis.com → 상점정보 → 부가정보에서 조회한다.
2. Vercel Production 환경변수
   - `PORTONE_STORE_ID`: 콘솔 → 결제 연동 → 연동 정보 → 식별코드의 상점 아이디(store-…)
   - `PORTONE_CHANNEL_KEY`: 위에서 만든 채널의 채널 키(테스트 → 실 연동으로 바꾸면 이 값만 바꾼다)
   - `PORTONE_API_SECRET`: 같은 화면의 V2 API Secret
   - `PORTONE_WEBHOOK_SECRET`(선택): 결제알림(Webhook) 관리 → 결제모듈 V2 → 웹훅 시크릿 발급. 넣으면 서명을 검사한다. 넣지 않아도 웹훅은 "어떤 결제를 조회할지"만 알려 주고 결과는 늘 포트원 API로 확인하므로 위조로 결제가 기록되지는 않는다.
   - 세 값이 없으면 결제 버튼에 "결제 설정이 아직 끝나지 않았어요."가 뜬다.
3. 예전 `INICIS_*` 환경변수는 더 쓰지 않는다(지금도 Production에 없다).
