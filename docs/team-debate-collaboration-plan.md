# 팀 토론 로비·채팅·작전시간 검토

> 후속 구현: 4단계 세션, 방별 시간·종료 방식, 팀 채팅 및 작전시간을 코드에 반영했다. 현재 구현 범위, 검증 및 DB 적용 순서는 [구현 안내](flexible-live-debate-implementation.md)를 따른다. 아래 내용은 최초 검토 기록이다.

## 이번 반영 범위

로비 인터페이스를 팀 슬롯 중심으로 재구성했다. 방 제목, 찬성·반대 참가자, 실제 준비 상태, 준비·시작 버튼이 기본 화면을 구성한다. 발언 역할 배정과 진행표는 접어서 제공한다. 팀 선택 전 참가자와 선택 사항인 진행자는 간단한 행으로 표시한다. 밝은 테마는 유지한다.

팀 채팅, 작전시간, 앞서 논의한 4단계 토론 전환은 아래 구현안으로 검토했으며 이번 UI 변경에 포함되지 않는다. 진행 순서와 필수 역할은 실제 서버 규칙과 일치하도록 유지했다.

## 팀별 채팅: 구현 가능, 먼저 텍스트로 도입

권장 UX는 로비와 토론 화면에서 같은 팀 대화를 이어 보는 것이다. 로비에는 팀을 선택한 뒤 `우리 팀 대화` 패널을 열 수 있게 하고, 1:1에서는 팀 대화가 필요하지 않으므로 숨긴다. 토론 중에는 접을 수 있는 팀 대화 패널과 읽지 않은 메시지 수를 제공하고, 작전시간에 자동으로 펼친다. 공식 발언 기록과 AI 평가에 팀 대화를 포함하지 않는다.

현재 로비가 Supabase의 참가자·방 변경 구독을 사용하므로, 별도 채팅 테이블과 접근 정책을 추가하는 방식으로 연결할 수 있다. 기존 공식 발언 테이블에 팀 메시지를 섞거나 전체 방에 전송한 뒤 화면에서만 걸러내지 않는다.

### 권한 및 데이터 설계 제안

- 메시지: `id`, `room_id`, `team_channel_id`, `sender_id`, `body`, `created_at`, 중복 전송 방지용 `client_message_id`.
- 서버가 로그인 사용자와 실제 참가자 소속을 확인해 발신자·팀을 결정한다. 클라이언트가 보낸 팀 이름만 신뢰하지 않는다.
- RLS로 해당 팀 채널에 접근할 수 있는 참가자만 조회·구독하도록 제한한다. 방장이나 진행자라는 이유로 상대 팀 대화를 볼 권한을 주지 않는다.
- 로비에서 팀 이동 시 기존 팀 메시지를 화면에서 즉시 지우고 구독을 해제한다. 팀 이동은 준비 상태 해제 후 허용하며, 시작 이후에는 팀 변경을 잠근다.
- 이미 읽은 내용을 되돌릴 수는 없으므로 UI에서 삭제하는 것만으로 팀 이동 후 비밀을 보장할 수 없다. 민감한 작전 대화는 팀 확정 후 시작하는 것을 기본으로 한다. 팀 구성 변경 시에는 새로운 채널 버전을 만들어 새 팀원이 이전 작전 기록을 받지 않도록 한다.
- 조회는 최근 메시지부터 제한해서 불러오고, 재접속 시 누락분을 다시 조회한다. 전송 실패·재시도·중복 제거와 길이·빈도 제한을 적용한다.
- 팀 채팅 보존 기간은 기관 정책과 함께 결정하며, 공식 토론 보고서 공유에는 포함하지 않는다.

Supabase Postgres Changes는 RLS와 함께 테이블 변경을 구독하는 방식을 제공한다. 실제 구현에서는 상대 팀 계정·비참가자 계정·팀 이동 전후 접근을 각각 검증해야 한다. [공식 문서](https://supabase.com/docs/guides/realtime/postgres-changes)

## 2:2·3:3 작전시간: 60초씩 두 번

권장 흐름은 다음과 같다. 각 작전시간은 양 팀이 동시에 사용하는 60초이며, 한 팀씩 순서대로 사용하지 않는다.

```text
찬성 입론 → 반대 입론
→ 작전시간 1분: 상대 입론을 분석하고 질문 준비
→ 찬성 주도 교차질문 → 반대 주도 교차질문
→ 작전시간 1분: 질의응답을 정리하고 반박 준비
→ 찬성 반박 → 반대 반박
→ 찬성 최종발언 → 반대 최종발언
```

1:1에는 기본적으로 적용하지 않는다. 방 개설에서 팀전 작전시간 사용 여부를 선택하고, 기본은 `1분 × 2회`로 제안한다. 기존 세부 단계 구조에 먼저 넣는다면 첫 휴식은 양측 입론 직후, 두 번째는 실제 첫 반박 직전에 넣어 전제 분석 단계와 충돌하지 않게 한다. 최종 목표는 앞서 논의한 4단계 시간 중심 구조에 통합하는 것이다.

| 발언·교차질문 시간 | 작전시간 | 예상 전체 시간 |
| --- | --- | --- |
| 10분 | 2분 | 12분 |
| 15분 | 2분 | 17분 |
| 20분 | 2분 | 22분 |

기본은 작전시간을 추가하는 방식이다. 방 개설·목록·로비에서 `토론 15분 + 작전 2분 = 총 17분`으로 보여 준다. 기관이 전체 15분 종료를 요구하는 경우에는 토론 13분 + 작전 2분으로 별도 설정한다. 기존 10·15·20분 발언 배분에서 자동으로 2분을 차감하지 않는다. 준비·자료 읽기 시간은 이 합계와 별개다.

### 작전시간 동작

- 공용 발언 입력과 공식 녹음을 멈추고, 팀 채팅과 60초 카운트다운을 표시한다.
- 양 팀의 작전시간은 동시에 시작하고 종료된다. 한 팀의 준비 완료만으로 다른 팀의 시간을 줄이지 않는다.
- 10초 전에 알리고, 종료되면 다음 공식 세션으로 전환한다. 마이크는 자동으로 켜지지 않고 발언자가 직접 활성화한다.
- 진행 권한이 있는 방장·진행자는 일시정지·재개·연장을 할 수 있고, 변경을 모두에게 알린다.
- 작전 대화와 시간은 공식 발언 점수·발언 횟수에서 제외한다.

### 현재 구조에서 필요한 변경

`src/lib/liveDebateCourse.ts`의 `getLiveDebateProgress`는 단계에 해당하는 첫 발언이 저장되면 단계를 완료한다. 시간은 권장값이다. 따라서 발언이 없는 60초 휴식을 기존 발언 단계 배열에 추가하는 것만으로는 진행되지 않는다.

`LiveDebateRoom.tsx`는 같은 단계 정보로 발언 권한, 타이머, 녹음 메타데이터, 종료와 평가를 결정한다. 작전시간은 별도의 단계 종류로 표현하고 공식 발언 단계와 구분해야 한다.

권장 서버 상태는 `course_version`, `phase_index`, `phase_kind`, `phase_started_at`, `phase_deadline_at`, `paused_at`, `remaining_seconds`, `revision`이다. 단계 종류는 `speech`, `cross_examination`, `strategy`로 구분한다. 공통 서버 전환 함수가 권한과 만료 시간을 검증하고, 트랜잭션과 revision 조건으로 중복 전환을 막는다. 클라이언트의 만료 요청은 서버가 시간을 확인한 뒤 처리하고, 재접속 시 이미 만료된 단계를 복구한다. 참가자가 없는 동안에도 즉시 전환해야 한다면 별도 서버 작업자를 둔다. 브라우저 타이머나 방장 접속에만 의존하지 않는다.

기존 방과 기록은 기존 버전으로 유지하고 새 방에 새 진행 규칙을 저장한다. 현재 `debateTiming.ts`의 시간 정규화는 10·15·20분에 맞추므로 사용자 지정 시간 및 작전시간 합계와 분리해야 한다. 로비의 역할 배정과 서버의 `start_live_debate_room` 필수 단계 검사도 새 과정 버전에 맞게 함께 변경해야 한다.

## 팀 음성 대화는 후속 단계 권장

현재 LiveKit 토큰은 하나의 토론방에 참가자를 넣고 발행·구독을 허용한다. 작전시간에 공용 마이크를 그대로 열면 상대 팀에도 들릴 수 있다. 초기 버전은 공용 음성을 차단하고 비공개 팀 텍스트 채팅을 사용하도록 제안한다.

팀 음성을 추가할 때는 서버가 팀 소속을 확인한 별도 팀 음성방 또는 트랙 구독 권한으로 상대 팀 접근을 차단해야 한다. 음소거나 클라이언트의 구독 해제만으로 비공개 권한을 보장하지 않는다. 공개 토론 복귀 시 재연결과 권한 복구까지 별도 검증한다. LiveKit은 발행자가 구독 허용 대상을 지정하는 트랙 권한 기능을 제공한다. [공식 문서](https://docs.livekit.io/transport/media/publish/)

## 권장 구현 순서와 검증

1. 이번 로비 UI 개편 적용.
2. 팀 텍스트 채팅: 테이블·RLS·소속 검사·실시간 구독·재시도·팀 이동 처리.
3. 서버 세션 진행 구조 및 4단계 토론·시간 설정 전환.
4. 팀전에 60초 작전시간 두 번 추가하고 채팅 패널 연동.
5. 필요 시 팀 음성과 기관 템플릿 확장.

검증에는 2:2·3:3 다중 브라우저, 1:1 휴식 미삽입, 타이머 동시 만료, 방장 이탈, 일시정지 중 재접속, 지연된 발언·녹음의 원래 세션 귀속, 상대 팀 채팅 조회 차단, 전송 중 팀 이동, 종료 이후 채팅 쓰기 차단, 총 시간 표시 일치를 포함한다.
