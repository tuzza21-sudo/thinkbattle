운영 DB의 발언 시각, 당시 수정 PR, Vercel 배포 이력을 대조했다. 서버 내부 오류와 재시도가 있었던 정황이 강하다. 지식·기억 검색을 중단하는 과정의 예외가 유력한 후보지만, 당시 원본 함수 로그를 다시 읽을 수 없어 정확한 발생 지점과 LLM 제공자의 관여 여부는 확정하지 못했다.

## ‘사회자 연결’이라는 표현의 출처

`src/lib/loungeApi.ts`의 `requestLoungeHost`는 1:1 캐릭터 응답에도 `/api/lounge`의 `action: 'host'`를 사용한다. 클라이언트와 서버의 공통 오류 문구에 과거 단체방의 ‘사회자’라는 표현이 남아 있다.

특히 `api/lounge.ts`의 최상위 예외 처리기는 예상하지 못한 오류의 메시지가 한국어가 아니면 다음 응답을 반환한다.

```json
{
  "error": "사회자 연결이 잠시 끊겼어요. 곧 다시 시도할게요.",
  "code": "lounge_internal_error",
  "retryable": true,
  "retryAfterSeconds": 3
}
```

HTTP 상태는 502다. 사용자가 기억한 문구는 이 경로와 맞지만, 당시 화면의 정확한 문구와 요청 ID가 없어 특정 응답 코드까지 확정할 수는 없다. ‘사회자’라는 단어만으로 단체방 진행자가 호출됐다고 판단할 근거는 없다.

`src/components/LoungePage.tsx`는 1:1의 재시도 가능한 오류에 3·6·12·24초, 이후 최대 30초 간격의 재시도를 적용하고, 연속 실패가 누적되면 오류를 표시한다. 반복 실패가 입력 후 수십 초의 정지처럼 보일 수 있다.

## 당시 대응과 배포

[PR #169](https://github.com/tuzza21-sudo/thinkbattle/pull/169)의 설명에는 당시 운영에서 한 이용자의 턴 중 약 절반에 `internal error`가 발생했고 페이지가 재시도했다는 기록이 있다. 이번 조사에서 당시 원본 로그를 직접 읽은 것은 아니며, 남아 있는 당시 대응 기록을 확인한 것이다.

해당 수정(`d1bfab9`, 운영 병합 `5c4027a`)은 다음을 변경했다.

- 지식·기억 검색의 중단 요청인 `lookupGiveUp.abort()`에서 예외가 나도 답변 요청 전체를 실패시키지 않도록 처리했다.
- 실패 로그에 `claimed`, `knowledge-wait`, `lookup-give-up`, `knowledge-done`, `reply-start` 등 처리 단계를 추가했다.

Vercel 운영 배포 `dpl_4YqJ829XU7K8x4RDa1PDjQhmejcy`는 15:31:28.667에 준비를 마쳤고, 15:31:28.893에 운영 별칭이 할당됐다. 이후 DB 응답 간격의 개선은 이 배포 시점과 일치한다. 다만 시간적 일치와 방어적 수정만으로 검색 중단이 정확한 원인이었다고 단정할 수는 없다.

## 조사 한계와 후속 개선

- Vercel은 당시 함수 로그 조회를 Hobby 요금제의 보관 기간 초과로 거절했다. CDN 요청 기록도 12시간을 넘긴 조회에 필요한 Observability Plus가 없어 조회하지 못했다. 따라서 당시 스택, LLM HTTP 상태, 실패 단계는 복원하지 못했다.
- 최근 30분의 `/api/lounge` 오류·경고 조회는 0건이었다. 이는 현재 무오류나 재발 방지를 증명하지 않는다.
- 서버 내부 처리 문제를 우선 의심할 근거는 있지만, LLM 장애나 제공자 연결 문제를 완전히 배제할 자료는 없다. 특정 LLM의 장애라고 판단할 근거도 확보되지 않았다.
- 재발 시 원인을 남기려면 요청 ID, 방 유형, 실패 단계, 제공자, 상위 HTTP 상태, 처리 시간을 대화 본문 없이 별도 보관하는 방식이 필요하다. 1:1 오류 문구의 ‘사회자’도 ‘답변’ 또는 캐릭터 이름으로 바꾸면 혼동을 줄일 수 있다.

초기 조사에서는 운영 데이터와 배포를 변경하지 않았다.

## 2026-11-10 후속 수정

기존 화면은 1:1 답변이 세 번 연속 실패하거나 응답·스트림 제한 시간이 지나면 공통 오류 문구를 표시했다. 이 예외 조건을 제거해, 반복 실패와 시간 초과도 기존의 자동 재시도로 복구하도록 수정했다. 열린 1:1 방의 일시적인 조회 실패도 화면을 유지한 채 다음 조회를 기다리며, 통화 전사 후 조회 오류를 전사 오류로 중복 표시하지 않는다.

실패 기록과 재시도는 유지한다. 로그인 만료, 접근 권한, 이용 한도 등 조치가 필요한 안내는 유지한다. 채팅과 통화의 반복 오류, 복구, 방 조회, 로그인·권한·한도 처리에 대한 회귀 테스트를 추가했다. 이 변경은 오류 문구의 노출을 제어하며, 서버 장애 자체의 재발 방지를 보장하지 않는다.
