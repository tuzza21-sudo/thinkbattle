# 라운지 사회자 공통 인스트럭션 개편

2026-10-03. 공통 규칙은 `api/lounge.ts`, 네 진행자의 개별 관점·말투·음성 지시는 `src/lib/lounge.ts`에서 정의한다. 공통 규칙이 캐릭터 예시보다 우선한다.

## 네 진행자의 구별되는 관점

네 명을 밝고 다정한 정도로만 구분하지 않고, 같은 발언에서 무엇을 발견하고 어떤 방향으로 이어갈지를 다르게 정의한다. 각 프롬프트에는 정체성, 주목하는 지점, 개입 방식, 다른 관점의 제시 방식, 다인 연결, 피할 반응, 구체적인 예시를 넣는다. 선택된 진행자 한 명의 지시만 기존 사회자 요청에 전달한다.

| 진행자 | 먼저 발견하는 것 | 주된 개입 | 음성 방향 |
| --- | --- | --- | --- |
| 재치 있는 진행자 | 예상과 결과의 어긋남, 공존하는 두 마음 | 짧은 반전·비유로 생각의 틈을 짚고 선택 기준을 확인 | 단정한 토크쇼 톤, 핵심 앞 짧은 쉼, 담백한 장난기 |
| 공감하는 진행자 | 표현된 감정, 마음에 걸린 가치 | 그 사람에게 무엇이 중요했는지 조심스럽게 확인 | 따뜻하고 안정된 호흡, 감정 표현에만 여유 |
| 활기찬 진행자 | 선택, 바꾸고 싶은 조건, 새로운 가능성 | 실제 발언의 조건 하나를 바꾸는 가정으로 기준을 드러냄 | 밝고 명료한 리듬, 선택지를 선명하게 강조 |
| 발랄한 진행자 | 단어, 맛·빛·소리, 기억나는 작은 행동 | 취향과 경험의 디테일 하나를 반갑게 발견 | 조금 높은 자연스러운 음역, 미소가 들리는 톤, 통통 튀는 억양과 짧은 쉼 |

같은 발언 “주인공이 떠난 건 이해되는데 무책임하게 느껴졌어요”에 대한 예시:

- **재치형:** “마음은 출발에 동의하는데 책임은 브레이크를 거는군요. 떠나는 방식이 달랐다면 받아들일 수 있었을까요?”
- **공감형:** “떠나고 싶은 마음은 이해하면서도, 남겨진 사람 쪽이 마음에 걸리신 걸까요?”
- **활기형:** “떠나기 전에 딱 한 행동을 바꿀 수 있다면, 무엇을 했어야 그 선택을 받아들일 수 있을까요?”
- **발랄형:** “그 마음을 갈라놓은 한 문장이나 작은 행동이 있었어요? 그 부분이 궁금해요.”

예시는 원하는 응답 방향을 설명하며 실제 모델 출력은 아니다. 작품의 실제 내용은 사전 자료와 참가자 발언으로 확인한다. 모든 차례에 대표 기법을 강요하지 않으며, 진지한 감정·자기소개·마무리·특정 참가자의 답변 차례에서는 상황과 공통 규칙을 먼저 따른다.

기존의 “항상 질문으로 연결”, 재치형의 “순서 발언에서 질문 변경 금지”처럼 새 공통 규칙과 충돌하던 지시를 제거했다. 모델·목소리 선택·재생 속도·API 호출 횟수는 유지하며 TTS의 읽는 방식 지시를 개별 관점과 맞췄다. 기존 녹음된 미리듣기 파일은 재생성하지 않았다. 새로운 음성 지시는 실제 생성되는 사회자 음성에 적용한다.

구성은 정체성·행동 규칙·입출력 예시를 구체적으로 제공하는 [OpenAI 공식 프롬프트 가이드](https://developers.openai.com/api/docs/guides/prompt-engineering)를 참고했다. 실제 개성 구분의 효과는 네 진행자에게 같은 대화 맥락을 주고 비교 청취해야 확인할 수 있다.

## 실제 참여 인원에 따른 역할

방의 최대 정원 대신 활성 멤버 중 최근 90초 내 생존 신호가 있는 사람을 센다. 기존 데이터에서 생존 신호가 비어 있으면 활성 멤버로 취급한다. 다음 사회자 요청에서 인원과 역할을 다시 판단한다.

| 사람 수 | AI의 역할 | 진행 방향 |
| --- | --- | --- |
| 1명 | 대화 상대 | 직접 받은 질문에 먼저 답하고, 상대의 생각을 따라 대화를 이어간다. 질문만 연속해서 던지지 않는다. |
| 2명 | 두 사람의 연결자 | 실제 발언의 공통점·차이를 연결하고, 사람이 서로 답할 자리를 마련한다. 각자 AI와 인터뷰하는 흐름을 피한다. |
| 3명 이상 | 그룹 사회자 | 나온 관점을 짧게 묶고 다음 사람의 경험을 연결한다. 순서·손들기·패스를 존중한다. |

이 변경은 AI의 응답 방식에 적용된다. 그룹 시작 조건, 순서 발언, 마이크 권한, AI 요청 간격은 기존 시스템을 따른다. 두 명이 참여한 순서 발언 방도 자동으로 자유 대화 방으로 바뀌지는 않는다.

## 핵심을 따라가는 반응

단순 재진술과 일반적인 칭찬에서 끝내지 않고, 발언의 핵심 주장·명시된 이유·표현된 감정에서 필요한 개입 하나를 고른다. 구체적인 공감, 판단 기준을 밝히는 질문, 근거 있는 다른 해석, 실제 참가자 관점의 연결이 선택지다. 매번 반론하거나 질문으로 마무리할 필요는 없다.

예를 들어 “주인공이 이기적이라 싫었다”는 발언에는 자기 행복을 선택한 점과 타인에게 책임을 미룬 점 중 무엇이 불편했는지 물을 수 있다. 이 예시는 응답 방향을 설명할 뿐, 실제 작품이나 참가자가 그 내용을 말한 것으로 간주하지 않는다.

보통 1~3문장, 필요할 때만 4문장, 260자 이내로 요청한다. 감정과 속마음을 추측하지 않으며, 다른 해석은 하나의 가능성으로 제시한다. 사전 자료의 사실과 해석을 구분하고, 스포일러·개인정보·불확실한 자료에 대한 기존 규칙을 유지한다.

## 순서 발언과 참가자 질문

서버의 발언 대상과 순서가 항상 우선한다. 일반·추가 발언에서는 현재 단계 목적 안에서 최근 발언에 연결한 질문으로 다듬을 수 있다. 자기소개는 참여 이유와 얻고 싶은 것, 마지막 단계는 정리·마무리를 유지한다. 손들기로 얻은 추가 차례에는 새 인터뷰를 강요하지 않는다.

특정 참가자에게 온 답변 차례(`kind=reply`)에서는 그 질문의 의미와 대상을 그대로 전달한다. AI가 대신 답하거나 다른 질문을 보태지 않는다. 답하거나 패스할 수 있는 선택을 유지한다.

## 맥락과 비용

최근 24개 메시지 중 마지막 두 사람 발언은 각각 저장 한도인 1,200자까지 전달한다. 이전의 긴 메시지는 시작과 끝을 합해 300자 안에 담아 결론이 모두 사라지는 문제를 줄인다. 메시지의 작성자 식별자는 유지한다.

누적 메모리에는 참가자별 관점과 이유, 생각의 변화, 공통점·차이, 미해결 질문과 발언 균형을 600자 이내로 요약하도록 요청한다. 답한 질문과 추측한 성격·감정은 담지 않는다.

모델은 `gpt-6-luna`로 유지한다. 사회자 텍스트 생성 1회와 공유 TTS 1회 구조를 유지하며, 추가 검색이나 별도 분석 호출은 넣지 않는다. 공통 프롬프트와 최근 발언 입력은 길어졌고, 텍스트·메모리 출력 여유를 위해 최대 출력 토큰은 600에서 900으로 늘었다. 실제 토큰 사용량과 음성 길이에 따라 비용과 응답 시간은 달라질 수 있다.

## 검증

모의 API 검사에서 같은 6인 정원 방의 실제 1·2·3인 역할 선택, 오래된 멤버 제외, 마지막 두 발언과 이전 발언의 결론 보존, 답변 차례의 질문·대상 보존, 기존 캐릭터·TTS 및 보호 기능을 확인한다. 실제 모델의 공감·질문 품질은 이 검사로 보장하지 않는다. 실제 1·2·다인 대화에서 반복 질문, 적절한 관점 연결, 과도한 개입, 응답 지연을 확인해야 한다.

API 배포로 반영되며 이 개편 자체에는 새 SQL 마이그레이션이 필요하지 않다.

## 2026-10-04 발랄형 음성 조정

마지막 발랄형(`dodi`)은 `gpt-4o-mini-tts`와 `coral`을 사용하며 속도를 1.07에서 1.12로 높였다. 음성 지시는 자연스럽게 조금 높은 성인 여성 음역, 미소가 들리는 밝은 톤, 핵심 단어의 통통 튀는 억양, 짧은 쉼, 또렷하고 산뜻한 문장 끝을 요청한다. 슬프거나 민감한 내용은 차분하게 존중한다.

이는 고정된 피치 수치를 지정하는 기능이 아니라 모델에 전달하는 연기 지시다. 실제 한국어 억양과 발랄함은 생성 결과를 듣고 확인해야 한다. 감정·억양·속도·톤의 지시 가능 범위는 [OpenAI TTS 공식 가이드](https://developers.openai.com/api/docs/guides/text-to-speech)를 따른다. 음성 예시는 같은 설정으로 `node scripts/generate-lounge-host-samples.mjs --host=dodi --overwrite`를 실행해 다시 만들 수 있다. 다른 진행자의 설정은 유지한다.
