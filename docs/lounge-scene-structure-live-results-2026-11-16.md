# 구조 개편 실제 응답 비교 — 2026-11-16

후속: 이 비교는 [서도현 카사노바형 바이블 전면 교체](./lounge-dohyun-casanova-replacement-2026-11-16.md) 이전 인물의 결과다. 새 바이블로 실제 생성한 결과는 아니다.

사용자가 승인한 GPT 6회·DeepSeek 2회를 실행했다. 운영 프롬프트와 두 가상 상황만 전송했으며 실제 사용자 기록·계정·DB는 사용하지 않았다. 원본 결과는 [8회 비교 JSON](./lounge-scene-structure-live-2026-11-16.json)에 보관했다. 자동 재작성·추가 재시도는 실행하지 않았다.

## 조건

모든 조건은 서도현, 주말 카페의 첫 맞선, 같은 사용자 발언과 6,000토큰 출력 여유를 사용했다. 이전 코드 스냅샷과 개편 코드를 실제 API 핸들러에서 캡처했다. 이전 버전에도 앞선 자기 이야기 허용·질문 반복 보정이 이미 들어 있었다.

현재 생활 추가 조건은 운동 뒤 허기, 일을 마쳐 가벼운 기분, 친구들에게 해 줄 주말 저녁 메뉴 고민을 테스트 데이터로 넣었다. 운영 캐릭터에 이 줄거리를 수동으로 추가한 것은 아니다. 이번 8회는 응답 생성 비교이며 실제 모델로 기록 호출까지 새로 8번 실행한 실험은 아니다. 저장·복구·다음 문맥 전달은 별도 로컬 회귀 검사 대상이다.

| 조건 | 인사 | 와인을 마시지 않는다는 말과 여행 취향 |
| --- | --- | --- |
| 이전 GPT | 공개 text 166자 | 271자 |
| 개편 GPT | 241자 | 도구의 JSON 해석 실패 |
| 개편 DeepSeek | 322자 | 452자 |
| 개편 GPT + 현재 생활 | 298자 | 308자 |

총 8회 중 7회는 JSON 답변을 읽었고 1회는 테스트 도구에서 `Invalid JSON response`로 끝났다. 당시 도구가 실패 원문을 남기지 않아 빈 응답·포맷·여러 텍스트 조각 등의 원인은 확정할 수 없다. 운영 파서에서 같은 실패가 재현됐다는 뜻은 아니다. 이후 도구가 실패 원문·완료 상태·사용량도 보존하도록 수정했다. 추가 호출은 하지 않았다.

## 확인한 개선과 남은 문제

인사에서 이전 GPT는 테니스·요리라는 취향 목록을 소개했다. 개편 GPT는 “어제도 파스타를 만들었는데 소스가 생각보다 잘 나와서 꽤 만족했죠”라는 자기 일화를 새로 만들었다. DeepSeek도 아침 테니스의 서브가 잘 안 들어갔다는 작은 경험과 당시 마음을 보탰다. 자기 일화를 모델이 직접 만들 수 있다는 점은 확인했다.

그러나 인사·첫 만남·취향 소개의 틀을 크게 벗어나지는 못했다. 현재 생활을 넣은 GPT도 바빴던 일과 일상 균형을 설명하는 데 머물렀다. 여행 취향 조건에서는 친구들 저녁 메뉴라는 기존 생활을 `attention`에서 지우고 ‘여행과 좋은 음식’이라는 현재 화제로 바꿨다. 생활 상태 칸을 두는 것만으로 독립적인 진행 중 이야기가 안정적으로 유지되지는 않았다.

DeepSeek의 여행 답은 존재하지 않는 앞선 자기 와인 발언을 가정하고 “아는 척한 꼴이 됐네요”라고 물러섰다. 이어 여행 경험을 말했지만 끝에는 대체 음료를 다시 물었다. 음료 질문 자체를 실패로 판정하지는 않는다. 다만 확인되지 않은 자기 실수에 대한 사과와 취향 조사로 돌아가는 흐름은 사용자가 지적한 문제에 가깝다. 인사 답의 ‘사용자가 긴장했다’는 판단도 주어진 인사만으로는 근거가 약하다.

이전 GPT 두 답도 질문 없이 자기 관점을 말했다. 따라서 이번 결과에서 질문 감소를 새 개편의 성과라고 주장할 수 없다. 지문·문장 수·질문 수 대신 실제 상황 반응과 자기 판단을 봐야 한다.

생성 여유는 모든 조건에 6,000토큰을 줬지만 정상 응답의 공개 text는 166~452자였다. 이 두 상황에서는 출력 상한만 높여도 풍부해지는 효과는 확인하지 못했다. 긴 답변을 쓸 수 있는 구조와, 그 여유를 좋은 장면으로 채우는 모델 능력은 구별해야 한다.

GPT 인사 요청의 실제 입력은 16,435토큰에서 13,238토큰으로 줄었다. 프롬프트 간결화와 예시 이동·새 상태 스키마가 함께 바뀐 비교이므로, 이것만으로 문체 변화의 단독 원인을 정할 수 없다. 모델별 토크나이저와 캐시 조건도 달라 비용·속도의 일반 비교로 확대하지 않는다.

## 결과를 보고 추가한 보강

`attention`은 대화 밖에서 이어지는 자기 생활·작업·관심사이며, 화제가 바뀌었다는 이유만으로 다른 주제로 덮어쓰지 않도록 명확히 했다. `body`는 주변 소품의 상태가 아니라 자신의 몸 상태라고 명시했다. 같은 설명을 출력 스키마에도 붙였다. 공개 답변의 순서·길이·자기 일화 횟수를 강제하지는 않는다.

이 보강 후 최종 인사 고정 지침은 19,237자다. 위 실제 비교의 개편 지침은 19,011자이며, 보강 후 검증은 로컬 검사와 요청 캡처까지다. 추가 실제 생성은 실행하지 않았다. 실제로 생활 보존이 얼마나 개선되는지는 다음 생성 평가에서 확인할 항목으로 남는다.

공통 구조 구현은 [구현·적용 문서](./lounge-scene-structure-update-2026-11-16.md)에 정리했다. 이번 결과는 두 상황·조건당 한 번씩의 소규모 비교다. Kindroid 수준의 전체 대화 품질이나 모델의 우열을 입증한 실험으로 보지 않는다.
