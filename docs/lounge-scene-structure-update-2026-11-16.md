# 캐릭터 생활·표현 공통 구조 개편 — 2026-11-16

[앞선 구조 제안](./lounge-kindroid-scene-voice-audit-2026-11-15.md)의 나머지를 구현했다. [자동 자기 이야기 생성·기록](./lounge-self-story-generation-2026-11-16.md)에 이어, 현재 상태·프롬프트 구성·문맥 보존·출력 저장 경로를 함께 바꾼다. 서도현 전용 변경이 아니라 기본 캐릭터와 사용자 제작 캐릭터의 일반 1:1 텍스트 대화 경로에 적용된다. 토론 사회자·단체방·음성 통화는 각 경로를 유지한다.

코드는 로컬에 반영했다. 운영 DB 마이그레이션과 배포는 실행하지 않았다. 긴 답변 활성화에는 아래 적용 순서가 필요하다.

## 무엇을 바꿨는가

| 제안 | 구현 | 기대 효과 |
| --- | --- | --- |

서도현 인사 상황에서 실제 API 요청을 캡처한 최종 고정 지침은 25,302자에서 19,237자로 줄었다(약 24%). 예시는 동적 입력으로 옮겼고 새로운 현재 상태 지침도 추가했으므로, 이 수치는 전체 입력 비용이 24% 줄었다는 뜻이 아니다. 인사 상황의 지침과 입력 합계는 29,885자에서 24,744자로 줄었다. 토큰 수와 글자 수는 다르다.

## 한 번의 대화가 이어지는 방식

1. 저장된 정체성·관계·현재 장소와 최근 대화, 관련 자기 이야기를 불러온다. 저장된 현재 생활 상태가 있으면 함께 제공한다.
2. 같은 응답 모델이 비공개 `character_life`와 공개 `text`·선택적인 `inner_voice`를 함께 작성한다. 별도 생활 생성·연출 API 호출을 추가하지 않는다.
3. 최종 채택된 답변의 현재 상태를 보관한다. 교정 답변이 채택되면 그 답변의 상태를 쓴다. 비공개 상태는 메시지나 음성에 출력하지 않는다.
4. 기존 응답 후 기록 호출은 실제로 말한 자기 일화와 그 의미, 진행·완료 상태를 기록한다. 답에 없는 사건을 기록기가 대신 창작하지 않게 한다.
5. 다음 대화에 현재 상태와 관련 이야기를 다시 제공한다. 실제로 한 선택과 결과를 이어 쓰고, 새로운 화제에는 같은 가치관과 다른 경험으로 반응할 수 있게 한다.

`character_life`는 가상 인물의 생활 상태다. 사용자 심리를 단정하거나 다음 답변의 작성 지침을 적는 칸이 아니다. 관계의 수치형 `mood`와 구별하며 서버가 턴과 기록 시각을 붙인다. 시간이 흐르거나 장소·대화가 바뀌면 모델이 변화를 반영한다. 매 턴 새 비극·비밀을 만들거나 저장된 이야기로 화제를 돌릴 의무는 없다.

기존 JSONB 상태와 순차 처리·버전 충돌 방지를 재사용한다. 비공개 상태는 복구 가능한 턴 작업에도 넣어 기록 실패 후 재처리에서 잃지 않게 했다. 이전 기록 응답에 새 필드가 없으면 기존 상태를 유지하며, 새 방 시작은 기존 초기화 정책을 따른다. 사용자·캐릭터 간 기록을 공유하지 않는다.

## 기억과 길이의 실제 한도

- 자기 이야기 보관: 최대 48개. 응답에는 관련성·진행 상태·최근성을 고려해 최대 4개만 제공한다.
- 기록기 문맥: 관련 이야기와 최근 이야기를 합쳐 최대 12개. 기존 ID를 사용해 같은 사건을 이어 기록한다.
- 자기 이야기의 요약에는 선택·결과, 의미에는 기분·까닭·자기 기준을 남긴다. 원문 근거를 검사하는 기존 경로를 유지한다. 모든 요약의 의미를 코드가 보증하는 것은 아니다.
- 최근 메시지 6개: 캐릭터 발화는 최대 3,000자, 사용자 발화는 기존 입력 한도 안에서 보존한다. 더 오래된 긴 발화는 앞뒤 약 1,000자를 보존한다. 최신 사용자 발언을 별도로 충분히 전달하는 기존 처리는 유지한다.
- 공개 대사·지문·속마음 저장 합계: 확장 활성화 시 최대 3,000자. 상한 초과 시 가능한 문장·문단 경계에서 마무리하고 대사를 우선한다. 매번 긴 답변을 채우라는 지시는 없다.
- 저장된 전체 발화와 속마음은 기존 메시지 렌더러로 표시한다. `LoungePage`의 생성 중·완료 직후 임시 표시에서 다시 1,200자로 자르던 두 곳을 제거했다. 저장 전후에 같은 긴 답변이 이어 보이게 한다.

이 보관함은 무제한 일기나 모든 과거 사건의 의미 검색 엔진이 아니다. 기존 장기 기억·경험 조회도 계속 사용한다. 서도현의 특정 실패 검사·1회 교정은 앞선 변경을 유지하며 다른 인물의 성격을 서도현처럼 만들지 않는다.

## 적용 순서

1. `supabase/migrations/20261219000000_lounge_companion_expression.sql`을 적용한다. 기존 마이그레이션 번호 다음에 오도록 이름을 정했다. 메시지 제약과 현재·구형 완료 RPC를 함께 갱신한다.
2. 해당 서버 환경에 `LOUNGE_EXTENDED_COMPANION_REPLIES=on`을 설정하고 코드를 배포한다.

플래그 기본값은 꺼짐이다. 기존 DB에서 새 코드가 먼저 실행되어도 저장 한도 1,200자를 지키며 활성 한도를 모델에 알려 준다. 현재 생활·프롬프트·기억 개편은 이 길이 플래그와 독립적이다. 플래그를 꺼서 길이 확장만 되돌릴 수 있다.

DB 제약은 호스트 메시지에 3,000자를 허용하되 완료 RPC는 비공개 1:1 텍스트 대화에만 확장 한도를 허용한다. 단체방·진행형 세션·음성 방의 기존 RPC 제한과 사용자 입력 1,200자를 유지한다. API의 음성 출력 한도는 600자다. 새 SQL은 기존 소유자·티켓·만료·세션 검사와 실행 권한을 유지한다.

오프라인 비교는 `node --preserve-symlinks --preserve-symlinks-main scripts/lounge-structure-probe.mjs`로 실행한다. 이전 코드 스냅샷과 보고서는 로컬 `node_modules/.cache/`에 보관한다. `--live`는 승인된 경우에만 외부 생성 API를 호출하며 자동 교정 호출을 꺼 총 8회로 제한한다. 두 가상 상황과 같은 6,000토큰 여유를 사용한다. 현재 생활을 제공한 조건의 생활 자료도 테스트용 가상 데이터이며 운영 캐릭터에 수동으로 넣지 않는다.

실제 비교에서 자기 일화는 나왔지만 일반적인 소개·취향 설명과 불필요한 사과·되묻기도 남았다. 생활 칸을 현재 화제로 덮어쓰는 응답을 보고 의미를 보강했다. 이 최종 보강 후 추가 유료 생성은 하지 않았다. 회귀 검사와 요청 캡처는 상태 전달·저장 경로의 검증이며 Kindroid 수준의 문체나 모든 상황의 창의성을 보증하지 않는다. 실제 문체는 최신 발언에 대한 반응, 인물 고유 판단, 자기 이야기의 관련성, 행동의 이유, 연속성, 자연스러움과 사용자 선택 존중을 보고 판단해야 한다. 질문 수만으로 평가하지 않는다.
