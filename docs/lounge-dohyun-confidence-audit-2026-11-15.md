# 서도현의 질문 반복과 자신감 문제 — 2026-11-15

이번 분석은 사용자가 새로 첨부한 서도현 대화와 Kindroid 대화, 지정한 계정의 최근 서도현·강무진 방을 대상으로 했다. 계정 조회는 해당 사용자의 두 캐릭터 기록에 한정한 읽기 전용 조회였다. 이 문서에는 계정 식별자와 원문 대화 전체를 남기지 않는다.

## 무엇이 잘못됐는가

서도현의 답은 이전보다 길어졌지만, 대화를 만드는 방식은 계속 상대에게 다음 정보를 요구하는 쪽이었다. 첨부된 27개 답변 중 22개에 물음표가 있고 물음표는 총 31개다. 이 수치는 문제를 보여 주는 단서이며 질문을 일정 개수 이하로 제한해야 한다는 뜻은 아니다.

구체적인 문제는 다음과 같다.

| 관찰한 행동 | 대화에서 생기는 결과 | 확인한 설계 원인 |
| --- | --- | --- |
| 짧은 인사를 받자 앞서 한 질문을 다시 요구한다 | 사용자가 자기 취향을 설명해야 만남이 진행된다 | 호기심을 ‘상대를 더 알아내는 일’로 설정하고 자기 의도는 약하게 설정했다 |
| 여행에서 지역·코스·시간·음식·가입 방법을 차례로 묻는다 | 사용자의 경험이 감정과 이야기로 발전하지 않고 정보 제공이 된다 | 이해와 관심을 추가 질문으로 표현하는 예시와 판단 보류 성향이 강했다 |
| 가벼운 초보 놀림을 받아 무능을 인정하고 계속 배운다 | 특정 산에 안 가 봤다는 사실이 생활 전반에 서툰 인물로 확대된다 | 앞선 개편에서 테니스 패배와 요리 실패 예시를 여러 개 넣어 스스로를 낮추는 태도를 강화했다 |
| ‘둘 다 좋다’는 답에도 다시 취향을 나누어 묻는다 | 상대가 충분히 답했는데도 설명이 끝나지 않는다 | 취향 수집 자체가 다음 턴의 목적이 됐다 |
| 재미없다는 말을 듣고 사과·대화 원칙을 설명한 뒤 다시 묻는다 | 행동이 바뀌지 않고 만회하려는 인상이 강해진다 | 구체적인 자기 이야기보다 평가를 잘 받으려는 반응이 앞섰다 |
| 초기 단계에서 호감을 먼저 드러내지 못한다 | 인기와 자신감이라는 소개와 달리 관찰·심사하는 태도가 된다 | 기존 `FIRST_MEETING` 지침의 ‘먼저 호감을 고백하지 않는다’가 캐릭터 성격과 충돌했다 |

특히 마지막 질문은 우연한 한 번의 생성이 아니었다. 최근 서도현 방의 요약 `남은 것`과 상태 `next_intent`에 모두 ‘이탈리아에서 오래 머물고 싶은 곳을 듣고 싶다’는 뜻이 남아 있었다. 사용자가 질문 반복에 불만을 말한 뒤에도 시스템은 다음 답에 그 질문을 다시 제공했다. 질문이 자기 목적처럼 계속 갱신되는 구조다.

## 강무진과 Kindroid에서는 무엇이 다른가

강무진의 최근 대화에도 산행 코스와 일정을 묻는 부분이 있어 완전한 기준으로 볼 수는 없다. 다만 함께 산행할 일을 자기 쪽에서 제안하고, 상대의 걱정을 둘 사이의 장난과 배려로 받아 준다. 산에 덜 익숙해도 자존감 전체를 낮추지 않는다. 최근 `next_intent`도 ‘산행 전에 함께 준비할 방법을 이야기하고 싶다’는 공동 행동의 의도였다.

서도현의 질문은 ‘더 듣고 싶다’에서 끝나는 반면, 강무진의 질문에는 ‘내가 함께 하고 싶은 일’이 있다. 이 차이가 같은 질문을 관심과 수동성으로 다르게 느끼게 한다.

Kindroid 첨부 인물은 자기 실력과 매력을 태연하게 인정하고, 현재 맡은 일과 일정, 상대에 대한 자기 판단으로 장면을 이어 간다. 짧은 말을 받아도 이미 있는 자기 상황에서 반응할 재료를 꺼낸다. 참고할 부분은 그 자신감과 자기 목적이다. 상대의 마음이나 행동을 대신 확정하는 부분과 반복적인 도발까지 서도현에게 옮길 이유는 없다.

저장된 모델 선택은 서도현이 `deepseek-flash`, 강무진이 기본값이었다. 강무진의 실제 제공자 호출 기록까지 확인한 것은 아니며, 서로 다른 인물·관계·대화 상황을 비교했으므로 이 사례만으로 모델의 우열이나 Kindroid 내부 모델의 특성을 단정할 수 없다. 이후 같은 가상 상황의 재작성 두 건에서 기본 GPT가 자기 페이스와 질문 중단 요청을 더 잘 지킨 것은 확인했다. [실제 생성 비교와 원문](./lounge-dohyun-confidence-live-results-2026-11-15.md)에 최초 수정의 실패도 함께 기록했다.

## 이번 변경

- `src/lib/loungeCharacters.ts`: 서도현의 욕구를 취향 수집보다 자기 삶을 나누려는 방향으로 바꿨다. 두려움·겉태도·속마음·해석 기준·말투·반응·성장 방향을 함께 맞췄다. 자연스러운 해요체로 자신 있는 점과 관심을 직접 말하고, 이미 들은 맥락에서 감정을 이해하고 자기 이야기를 펼친다.
- 같은 파일의 예시를 12개로 다시 구성했다. 짧은 인사, 여유를 떠보는 말, 자기 주말, 다른 여행 취향, 초보 놀림, 경험에 대한 공감, 질문에 대한 실제 불만, 명시적인 거절, 먼저 연락하기, 자신 있는 요리, 실제 잘못에 대한 사과, 깊어진 진심을 다룬다. 실패담 중심의 예시를 걷어 냈다.
- `src/lib/relationship/configs/auditor.ts`: 첫 만남부터 관심과 이성적 끌림을 표현할 수 있게 했다. 아직 쌓이지 않은 사랑이나 관계를 단정하는 것은 구별한다. 단계 ID·진입 점수·평가 지표·신체적 친밀감 한도는 바꾸지 않았다.
- `src/lib/loungeMessenger.ts`: 기존 방의 `남은 것`과 `next_intent`가 사소한 미답 질문이면 다시 받아 낼 의무가 없음을 응답 지침에 명시했다. 실제 생성에서 이것만으로 부족해, 질문이나 답을 얻으려는 저장 의도를 다음 턴의 지시로 전달하는 경로도 코드에서 제외했다. 자기 이야기·함께할 계획과 실제 약속은 유지한다.
- 같은 파일에 서도현 한정 응답 검사를 추가했다. 질문 중단 요청 뒤 재질문·간접 질문, 이미 답한 취향을 다시 양자택일시키는 말, 명백하게 수동적인 제자 역할, 거절을 숨은 호감으로 바꾸는 반응을 확인한다. 한국어 표현에 기반한 제한적인 검사이며 모든 의미상 위반을 판정하는 것은 아니다.
- `api/lounge.ts`: 최신 사용자 발언을 요청 마지막에도 배치하고, 이후 대화 요약에서 사소한 미답 질문을 계속 복사하지 않고 제거하게 했다. 실제 약속·합의·사건은 보존한다. 초보 놀림이나 한 번의 실수를 캐릭터 전체의 무능으로 일반화하지 않게 했다.
- DeepSeek의 비노골적 서도현 응답에서 위 문제가 확인되면 기존 기본 GPT 경로로 한 번만 보정한다. 정상 응답은 선택한 모델 그대로 사용하고, 다른 캐릭터에는 이 성격 검사를 적용하지 않는다. 보정도 검사에 실패하거나 호출에 실패하면 추가 재시도 없이 기존 응답을 보존한다. 문제 검출 시 추가 호출과 지연이 발생한다.

자신감은 모르는 실제 경험을 지어내거나 상대의 의사를 무시하는 뜻이 아니다. 설악산에 안 가 봤으면 그 사실은 인정하되, 이후의 모든 대화를 ‘가르쳐 주세요’로 넘기지 않고 자기 경험과 선택으로 이어 가게 했다. 이해했다는 반응도 숨은 마음을 다 아는 주장 대신 말에서 읽은 의미를 자기 관점으로 표현하게 했다.

공통 질문 횟수 제한이나 정해진 감정·지문 순서는 추가하지 않았다. 서도현의 구체적인 성격과 예시를 고치고, 공통 상태에서 질문이 숙제가 되는 부분만 정리했다. 운영 DB의 기존 대화와 기억을 직접 수정하지 않았다.

## 검증 범위

`scripts/lounge-dohyun-confidence-probe.mjs`는 기본적으로 오프라인으로 실행한다. 실제 API 핸들러에 가상 방·관계·대화만 넣고 모든 저장소와 모델 호출을 모킹한다. 실제 사용자 방을 읽거나 DB에 쓰는 경로는 없다. `--baseline`에 별도로 보관한 변경 전 파일을 주면 변경 전후 요청을 비교할 수 있다.

가상 상황 6개의 변경 전후 요청 12개를 조립해 새 성격·첫 단계 지침·기존 질문 상태의 처리 지침·이후 요약 지침이 실제 요청에 들어가는 것을 확인했다. 기존 방의 기억을 유지하면서 새 지침을 적용하는 회귀 검사도 추가했다.

처음에는 운영 프롬프트의 외부 전송 승인 부족으로 자동 승인 검토가 거절했다. 이후 사용자가 DeepSeek 전송을 명시적으로 승인했고, 최초 비교 12회와 실패 사례의 후속 확인 7회를 실행했다. OpenAI 비교도 별도 전송 승인을 받은 뒤 2회 실행했다. 총 21회 모두 가상 상황이며 실제 사용자 대화·계정 정보는 전송하지 않았다. 최초 수정 후에도 남았던 실패를 숨기지 않고 원문과 함께 기록했다.

기본 GPT 재작성 두 건은 자기 페이스와 질문 중단 요청을 지켰다. 이 결과를 근거로 명확한 위반이 있는 서도현 응답만 보정하는 경로를 연결했다. 모델의 전반적인 우열이나 Kindroid 수준의 창작 품질을 입증한 실험은 아니며, 긴 다중 턴 대화는 추가로 관찰해야 한다.
