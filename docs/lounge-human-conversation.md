# 사람끼리 이야기하는 라운지의 AI 역할

2026-10-04 변경. 발언 순서를 관리하는 시스템과 AI의 음성 응답을 분리한다. 사람의 발언이 끝났다는 이유만으로 AI를 호출하지 않는다.

| 상황 | 동작 |
| --- | --- |
| AI와 혼자 대화 | 직접 대화 상대가 되어 응답한다. 실제 연결된 사람이 한 명인 자유 대화도 같은 방식이다. |
| 두 명 이상 참여 | 시작할 때 짧게 안내하고 첫 질문을 건넨다. 이후 사람끼리 대화하도록 기다린다. |
| 참가자가 다른 참가자에게 질문 | 자유 대화에서는 상대가 바로 답한다. AI가 질문을 되풀이하거나 대신 답하지 않는다. |
| 사회자에게 도움 요청 | 모든 참가자가 `사회자 도움` 버튼을 사용할 수 있다. 전사된 말이 `사회자, 어떻게 생각해?`처럼 AI를 직접 부르는 요청이면 응답을 예약한다. |
| 잠깐의 침묵 | 기다린다. 사람의 말이 끝날 때마다 칭찬·요약·다음 질문을 덧붙이지 않는다. |
| 긴 침묵 | 마지막 사람의 음성·전사 이후 30초 이상 조용하고, 마지막 AI 요청 이후 90초 이상 지났을 때만 짧게 돕는다. |
| 문제 발언 | 전사는 먼저 표시하고 별도 검토로 경고·제한을 적용한다. 자유 대화에서도 제한된 사람의 음성과 전사 요청은 막는다. |

## 세션과 화면

2026-10-05: 방 생성 직후 자료 준비 요청을 시작하고 방장 화면의 대기방에서도 이어서 확인한다. 음성 연결이나 대화 시작을 기다리지 않는다. 생성 화면과 방 화면은 같은 준비 요청을 공유하고 서버의 조사 티켓으로 중복 작업을 막는다. 사회자는 조사 진행 멘트를 말하지 않으며 패스 안내는 첫 인사에서 한 번만 한다.

프로필과 발언 대기 명단은 위에, 말하기·마이크·손들기 버튼은 아래에 고정한다. 사회자 발언·주제 안내·참가자 발언이 있는 가운데 대화창만 세로로 스크롤한다. 현재 차례는 프로필에서 표시하고 화면 아래의 중복 표시를 없앴다. 좁은 화면에서 현재 발언자의 프로필이 가려지면 프로필 줄을 가로로 이동한다.

순서 발언에서 실제로 말한 뒤 10초 동안 음성이 없으면 마지막 전사를 저장한 후 기존 `done` 동작으로 다음 차례로 넘긴다. 아직 발언을 시작하지 않은 차례와 자유 대화에는 적용하지 않는다. 발언자 브라우저가 실행 중일 때 동작하며 별도 SQL 변경은 없다.

- 자기소개와 마지막 정리는 순서 발언을 사용한다. 모두에게 차례가 돌아가고 패스할 수 있다. 자기소개에서는 참여 이유나 대화를 통해 얻고 싶은 것을 묻는다.
- 주제별 가운데 네 단계는 각각 **순서 발언 → 자유 대화**로 진행한다. 기본 차례에서는 한 명씩 이야기하거나 패스한다. 모두의 기본 차례와 예약된 질문 답변이 끝나면 같은 주제에서 모두의 마이크를 연다. 다음 주제로 넘어가면 다시 순서 발언부터 시작한다. 단계마다 첫 발언자를 순환해 같은 사람이 항상 먼저 말하지 않게 한다. 중도 입장자는 진행 중인 기본 라운드의 끝에 추가하고, 자유 대화에 들어온 사람은 다음 주제부터 기본 차례를 받는다.
- 자유 대화의 손들기는 이어서 할 말이 있다는 표시다. 명단을 화면에 보여 주며 독점 발언권을 배정하지 않는다. 사용자가 손을 내리거나 다음 이야기로 넘어갈 때 표시가 해제된다.
- AI는 각 주제 시작에 한 번만 질문과 참여 방식을 짧게 안내한다. 다음 참가자로 넘어갈 때마다 답하거나 평가하지 않는다. 화면은 현재 주제와 함께 `순서 발언` / `자유 대화`를 표시한다.
- 단계별 시간 합계는 약 30분을 목표로 한다. 시간이 지나도 기본 차례를 건너뛰지 않고, 기본 차례를 마친 뒤 자유 대화를 최소 1분 확보한다. 사람이 많은 방이나 긴 발언은 목표 시간보다 길어질 수 있다. 자유 대화 중 음성·전사·AI 응답이 진행 중이면 자동 전환을 기다린다. 방장은 자유 대화에서 `다음 이야기로` 버튼으로 전환할 수 있다. 기본 차례 중에는 다음 주제로 건너뛸 수 없다.
- AI 요청은 방에 저장된다. 다른 참가자가 요청해도 방장 브라우저가 음성 방송을 수행한다. 기존 방장 브라우저 의존성은 유지된다.

음성 호출은 별도 LLM 판정을 추가하지 않고 저장된 전사에서 직접 호칭과 요청 표현을 확인한다. 인식 결과가 다르거나 호칭 없이 질문하면 호출되지 않을 수 있으므로 버튼을 함께 제공한다. 사용자가 전사되는 동안에도 대화를 계속할 수 있다.

## 주제별 대화 흐름

2026-10-04 공통 순서 중 가운데 네 단계의 이름과 기본 질문을 방장이 선택한 분야로 구분한다. 자기소개·마무리, 단계별 시간과 자유 대화의 마이크 동작은 동일하다. 대화창의 안내, 프로필 아래 진행 상태, AI에 전달하는 단계·질문에 같은 구성을 사용한다.

| 분야 | 중간 대화 흐름 |
| --- | --- |
| 영화 | 감상 → 기억에 남는 장면 → 인물의 선택과 해석 → 결말과 다른 관점 |
| 책 | 읽고 난 느낌 → 문장과 대목 → 작품의 생각과 해석 → 내 삶과 연결 |
| 취미·취향 | 취향의 출발점 → 경험과 발견 → 취향이 다른 이유 → 다음에 즐길 것 |
| 연애·사랑 | 지금 마음과 관계 → 어려웠던 상황 → 서로의 필요와 경계 → 원하는 관계 |
| 커리어·진로 | 현재 상황과 고민 → 일하며 겪은 경험 → 선택지와 기준 → 다음 시도 |
| 재테크·경제 | 관심과 목표 → 투자·소비 경험 → 근거와 위험 → 나에게 맞는 원칙 |
| 자녀·교육 | 아이와 궁금한 점 → 실제 육아·교육 경험 → 아이와 부모의 입장 → 우리 집의 시도 |

사전 조사 질문은 기존처럼 뒤쪽 두 단계에서 활용하며 참가자끼리 전달한 질문은 우선한다. 방 소개가 없는 예전 방은 장면·결말을 요구하지 않는 일반 경험 질문을 사용한다. 기존 사회 이슈 방은 해당 분야의 흐름을 유지한다. 주제별 문구에는 추가 LLM 호출이 필요 없다. 배포된 UI와 API에 함께 반영해야 한다. 순서 발언 뒤 자유 대화로 전환하는 흐름은 아래의 후속 마이그레이션으로 적용한다.

## 적용과 검증

SQL Editor에서 기존 마이그레이션을 `20261004030000_voice_lounge_education_topics.sql`까지 적용한 뒤 `20261004040000_voice_lounge_round_then_free.sql` 전체를 실행한다. 이어서 클라이언트와 API 변경을 함께 배포한다. 새 코드가 사용하는 RPC와 세션 상태가 있으므로 SQL을 먼저 적용한다. 이 작업에서는 원격 DB에 실행하지 않았다.

새 SQL은 이미 진행 중인 자유 대화를 유지하고 다음 주제부터 기본 라운드를 시작한다. 새 방의 가운데 단계는 처음부터 기본 라운드로 시작한다. 다시 실행해도 자유 대화 시작 시간을 초기화하거나 기존 차례를 바꾸지 않는다.

모의 API와 호출 타이밍 검사, 격리 PostgreSQL의 순서 → 자유 대화 → 정리 전환·직접 호출·권한·제한·재실행 검사, 실제 오디오 훅을 합성 트랙으로 연결한 브라우저 검사, TypeScript와 프로덕션 빌드를 검증했다. 실제 여러 사람의 마이크와 유료 AI의 대화 품질은 실사용 검증이 필요하다.
