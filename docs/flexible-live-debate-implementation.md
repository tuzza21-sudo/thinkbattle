# 사람 대 사람 토론: 4단계 세션

새 토론방은 `입론 → 교차질문 → 반박 → 최종발언`으로 진행한다. 전제 분석과 충돌 비교는 각 단계 안에서 수행하는 사고 역량으로 평가하며, 별도의 필수 발언 세션으로 요구하지 않는다. 기존 `session_config IS NULL` 방은 이전 화면과 서버 함수를 사용한다.

## 방 개설과 로비

- 기본: 15분, 자동진행, 팀 내 자유 참여. 10분은 핵심 쟁점 연습, 20분은 심화 토론용이다.
- 각 단계의 한 팀 시간을 30초~15분, 15초 간격으로 선택한다. 양 팀 동일 시간이 기본이며 찬성·반대를 따로 조정할 수 있다.
- 단계를 생략할 수 있지만 최소 한 단계가 필요하다.
- 2:2·3:3은 교차질문 전과 반박 전에 양 팀이 동시에 사용하는 작전시간 각 60초를 기본으로 추가한다. 작전시간은 끌 수 있고, 생략된 단계 앞의 작전시간도 제거된다.
- 시간 표시는 작전시간을 포함한 실제 합계다. 기본 팀전은 토론 15분 + 작전 2분 = 총 17분이다.
- 자유 참여에서는 발언 가능한 팀의 누구나 발언한다. 단계별 담당자 모드는 로비에서 각 팀의 활성 단계 담당을 정해야 시작할 수 있다.
- 로비에서 방장이 진행 설정을 바꾸면 전원의 준비 완료가 해제된다. 시작 후 설정·팀·역할은 고정된다.

| 발언 시간 | 입론 / 팀 | 교차질문 / 주도 측 | 반박 / 팀 | 최종발언 / 팀 | 작전 포함 팀전 |
| --- | --- | --- | --- | --- | --- |
| 10분 | 1분 | 1분 30초 | 1분 30초 | 1분 | 12분 |
| 15분 | 2분 | 2분 30초 | 2분 | 1분 | 17분 |
| 20분 | 2분 | 3분 | 3분 | 2분 | 22분 |

## 실제 진행

찬성 교차질문에서는 찬성이 질문하고 반대가 답한다. 반대 교차질문에서는 반대가 질문하고 찬성이 답한다. 질문·답변을 별도 단계로 나누지 않으며, 세션 내 교환 횟수를 제한하지 않는다. 공식 발언을 전송해도 다음 단계로 넘어가지 않는다. 역할 안내로 질문 측과 답변 측을 구분하며, 발언 내용의 의미나 엄격한 질문·답변 교대는 강제하지 않는다.

자동진행은 저장된 서버 마감 시각이 지나면 다음 세션으로 전환한다. 진행자 진행에서는 초과시간을 표시하고 방장 또는 진행자가 다음 세션을 시작한다. 두 모드 모두 방장·진행자가 일시정지, 재개, 30초 연장, 다음 세션을 사용할 수 있다. 마지막 세션의 다음 버튼은 토론을 마친다. 진행자가 입장하지 않은 방은 방장이 제어한다.

서버 상태에는 현재 세션, 마감 시각, 일시정지 상태, 버전, 실제 단계별 경과시간을 보관한다. 중복·오래된 제어 요청을 거절하며, 새로고침과 재접속 시 서버 시각을 기준으로 복원한다. 활성 클라이언트가 2초 간격으로 동기화한다. 모두 접속을 끊은 경우 백그라운드 작업을 실행하지 않고, 다음 접속·요청에서 누락된 자동 전환을 마감 시각에 맞춰 따라잡는다. 진행자 모드에서 제어 가능한 사람이 모두 나가면 다른 사람이 자동으로 진행자 권한을 얻지는 않는다.

팀 채팅은 로비와 토론 화면에서 이어진다. 서버가 참가자의 실제 팀과 현재 팀원 구성을 기준으로 채널을 결정하고 RLS로 조회·구독을 제한한다. 진행자나 상대 팀은 읽을 수 없다. 팀원 구성이 바뀌면 이전 구성의 메시지는 표시되지 않는다. 이미 읽은 정보까지 회수하는 기능은 아니다. 최근 100개를 표시하며 메시지는 최대 1,000자, 10초에 10개로 제한한다. 공식 발언·평가·공유 보고서에는 포함되지 않는다. 별도의 채팅 자동 삭제 주기는 추가하지 않았다.

음성은 전체 방 발언용 LiveKit 연결을 사용한다. 팀 작전시간에는 공식 마이크를 중지하고 팀 텍스트 채팅을 사용한다. 음성은 최대 1분씩 녹음하고 이어서 다시 발언할 수 있다. 녹음 종료 후 전사·저장과 다음 발언을 별도로 처리한다. 서버의 녹음 시작 티켓이 원래 단계와 시작 시각을 보존하므로 늦게 도착한 전사를 다음 단계에 잘못 붙이지 않는다. 녹음 종료 후 5분 내 저장을 재시도할 수 있으며, 처리 실패한 전사는 수정하거나 취소할 수 있다. 최종 평가는 유효한 녹음 티켓이 모두 저장·취소·만료된 뒤 가능하다. 전송·전사 중에는 화면을 유지해야 하며 브라우저를 닫은 녹음을 복구하는 기능은 없다.

토론 종료 후 공식 기록과 개인 평가는 기존 ‘내 기록’에 저장된다. 방·참가자별로 같은 기록 ID를 사용해 재접속 시 중복 기록을 만들지 않는다. 팀 작전시간은 경과시간 합계에 포함하고 일시정지 시간은 제외한다. 평가는 실제 활성 단계와 역할 정보를 받으며, 전제 분석·충돌 비교를 별도 단계로 수행하지 않았다고 감점하지 않도록 안내한다. 새 형식에서는 최근 80개 발언만 사용하는 제한을 제거했다. 평가 입력이 180,000자를 넘으면 기록을 보존하고 평가 제한을 안내한다.

## 적용 순서

코드 수정만으로 원격 Supabase의 구조가 바뀌지는 않는다. 아래 SQL을 해당 환경에 먼저 적용한 다음 프런트엔드를 배포해야 새 방을 사용할 수 있다.

1. 기존 실시간 토론방 스키마와 운영 보강, 음성 저장 마이그레이션이 적용된 환경을 사용한다. `live_debate_rooms`, 참가자·발언·개인 평가 테이블, `audio_path`, 기존 로비 RPC가 선행 조건이다.
2. `supabase/migrations/20260911000000_flexible_live_debate_sessions.sql`을 한 번 적용한다. 기존 RPC를 `_v1`로 보존하고 새 방 전용 분기를 추가하며 세션·녹음 티켓·팀 채팅 테이블과 Realtime publication을 설정한다. 기존 데이터를 삭제하거나 새 형식으로 자동 변환하지 않는다.
3. 프런트엔드 배포 후 새 1:1 방과 2:2 방을 실제 계정으로 만들어 준비·시작·재접속·종료를 확인한다. 음성 방은 기존 LiveKit/Gemini/Storage 설정이 필요하다.

새 DB 구조가 없는 환경에서 4단계 방을 개설하면 서버 업데이트가 필요하다는 안내를 표시한다. 사용자 선택과 다른 이전 형식의 방을 대신 만들지는 않는다. 이번 작업에서는 원격 DB 적용이나 서비스 배포를 수행하지 않았다.

## 검증

- `npm run build`: TypeScript 및 프로덕션 빌드.
- 변경한 소스에 대한 ESLint 검사.
- `npm run test:session`: 시간 합계, 생략 단계, 발언 권한, 일시정지·초과시간 계산.
- PostgreSQL 통합 검증: 실제 기존 토론방 마이그레이션과 새 마이그레이션을 임시 PGlite 엔진에 적용하고 RLS, 설정 변경, 준비 해제, 역할 잠금, 발언 재시도, 시간 제어, 문답 반복, 늦은 전사, 평가 대기, 이전 방 호환을 검사한다.

```powershell
npm.cmd install --prefix node_modules/.cache/debate-sql-check --no-package-lock --no-audit --no-fund @electric-sql/pglite
$env:TEST_SESSION_SQL = '1'
npm.cmd run test:session
```

UI fixture: 개발 서버의 `/scripts/live-session-preview.html`, 설정 화면은 `?settings=1`. 네트워크 요청은 로컬 fixture 응답으로 대체되며 실서비스를 변경하지 않는다. Chrome CDP 9238 포트에서 fixture를 연 뒤 `node scripts/live-session-ui-check.mjs`로 검증한다. 1440·768·390·320px 배치, 반복 질문, 팀 메시지, 일시정지·재개·전환, 작전시간 차단, 기본 시간 및 양측 개별 시간을 확인했다. 실제 다중 계정 LiveKit 음성 송수신·전사 통합은 이 fixture 검증에 포함되지 않는다.
