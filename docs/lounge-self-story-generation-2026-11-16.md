# 캐릭터 자기 이야기 자동 생성·기록 — 2026-11-16

후속: 이 문서는 첫 자동 기록 변경과 당시 검증 결과다. 이후 [공통 구조 개편](./lounge-scene-structure-update-2026-11-16.md)에서 현재 생활 상태·프롬프트·문맥·저장 한도를 추가 구현하고 자기 이야기 보관을 12개에서 48개로 확장했다. 현재 적용 순서는 후속 문서를 따른다.

캐릭터 제작자가 매번 진행 중인 이야기를 넣어 주는 방식 대신, 응답 모델이 기본 설정과 이미 말한 사실 안에서 자기 일화를 만들고 기존 기록 단계가 그 이야기를 보존하게 했다. 모든 기본·유저 제작 캐릭터가 사용하는 1:1 동반자 채팅 경로의 변경이며, 특정 캐릭터의 이야기 목록을 새로 수작업으로 넣지 않았다.

## 동작

1. 응답 모델은 프로필·성격·현재 장면·사용자 발언을 바탕으로 관련 있는 자기 생활이나 경험을 자율적으로 이야기할 수 있다. 제작자가 줄거리를 제공할 때까지 기다릴 필요가 없다.
2. 기존 응답 후 기록 호출이 실제 캐릭터 대사에서 새 자기 이야기와 그 일에 드러난 감정을 추출한다. 기록 모델이 대사에 없던 사건을 별도로 창작하지 않는다.
3. 요약·기분과 이유·진행 상태·근거 대사·안정적인 ID를 기존 방 상태 JSONB에 저장한다.
4. 다음 응답과 사전 분석에는 현재 화제에 관련 있는 이야기, 진행 중인 이야기, 최근 이야기를 골라 제공한다. 기록 모델에는 기존 ID 목록을 제공해 같은 이야기를 수정하고 끝낼 수 있게 한다.

기존 사실을 매번 새로 바꾸는 기능은 아니다. 같은 경험을 현재의 기분과 사용자 말에 따라 다른 관점에서 이야기하고, 설정에 맞는 새 경험을 보탤 수 있도록 했다. 저장된 이야기는 선택 가능한 재료이며 모든 화제를 그 줄거리로 돌리라는 지시가 아니다.

## 구현 범위

- `src/lib/loungeMessenger.ts`: 공통 자기 생활 생성 지침, `LoungeSelfStory`, 기록 파서·갱신·관련성 선택·정규화, 응답 후 `self_story_updates` 스키마를 추가했다.
- `api/lounge.ts`: 분석기·응답 작성자·기록 단계에 자기 이야기 문맥을 연결했다. 새 이야기를 위한 별도 생성 호출은 추가하지 않았다.
- 기록 출력의 최대 여유는 동반자 채팅에 한해 3,000에서 4,200토큰으로 조정했다. 호출 횟수는 같아도 자기 이야기 문맥과 기록량에 따라 입력·출력 사용량은 늘 수 있다.
- `scripts/lounge-self-stories.test.mjs`: 생성된 일화 저장과 다음 답 전달, 같은 ID의 진행·완료, 근거 없는 기록과 사용자 발언 재저장 차단, 실패·지연된 갱신, 중복·용량·관련성·방 초기화를 검사한다.
- 실제 API의 기존 원자적 상태 저장 회귀 검사에도 자기 이야기 저장과 다음 턴 재사용을 추가했다. 두 턴에 기존 작성·기록 호출 네 번만 사용하는지 확인한다.

## 저장 기준과 한도

`self_stories`는 현재 사용자의 현재 캐릭터 방 상태에 속한다. ‘처음부터 하기’와 방 변경은 기존 초기화 동작을 유지하며, 다른 사용자나 캐릭터의 기록을 합치지 않는다.

최근 이야기 12개를 보관하고 응답에는 최대 4개를 선택한다. 갱신은 한 번에 최대 2개이며, 요약 180자·감정과 이유 100자·근거 대사 200자로 제한한다. 이 한도는 기록 크기를 관리하는 값이며 사용자에게 보이는 대사의 개수나 이야기 표현 횟수 제한이 아니다.

기록의 근거는 방금 캐릭터가 실제 말한 구절이어야 한다. 대사에 없는 사건, 사용자 발언을 그대로 되풀이한 구절, 알 수 없는 기존 ID와 상태는 코드에서 받지 않는다. 속마음만의 추측을 확정된 자기 사건으로 올리지 않는다. 감정·이유도 실제 대사나 속마음에 드러난 내용만 기록하도록 지시한다.

원문 구절 확인은 기록의 모든 의미를 자동으로 검증한다는 뜻은 아니다. 요약과 인물 설정의 정합성, 말투와 일화의 창작 품질은 여전히 생성·기록 모델의 능력에 영향을 받는다. 현재의 저장·재사용 기능이 Kindroid 수준의 대화 품질을 보장하는 것은 아니다.

기존 방은 새 기록이 생기면 사용하기 시작한다. 기존 `self_facts`와 대화 요약을 지우거나 운영 DB를 직접 갱신하지 않았다. 이번 변경에 새 SQL 마이그레이션은 필요하지 않으며 기존 상태 저장 구조를 사용한다. 운영 배포는 별도다.

실제 생성 검증은 사전 자기 이야기 기록 0개에서 시작했다. 모델이 주말 테니스와 식사 일화를 만들었고, 기록 모델이 원문 구절·요약·감정적 의미를 추출했다. 이어진 응답은 같은 경험에 대한 감정을 설명했다. [가상 검증 원문](./lounge-self-story-live-2026-11-16.json)을 보관했다. 이는 생성·기록·후속 사용을 확인한 사례이며, 일화의 현실적 세부 정합성이나 모든 캐릭터의 문체 품질까지 검증한 실험은 아니다.

`scripts/lounge-self-story-probe.mjs`는 저장된 가상 요청에서 시작해 위 3회를 재현한다. 기본값은 오프라인이며, 실사용자 방을 조회하거나 DB에 쓰는 기능은 없다. 자동 승인 검토는 새 외부 전송 3회에 별도 승인이 필요하다고 처음 거절했고, 사용자의 명시적 승인 뒤 같은 준비된 요청을 실행했다.

전체 프롬프트 간결화, 독립적인 하루 상태·몸 상태 설계, 장기 이야기 보관 확대, 최종 1,200자 저장 상한 변경은 이번 기능에 포함되지 않는다. 앞선 [구조 분석](./lounge-kindroid-scene-voice-audit-2026-11-15.md)의 일부를 구현한 것이다.
