# 라운지 주제 분야와 방 소개

메인에서 분야와 세부 항목을 고른 뒤 방 제목을 직접 입력한다. 분야 선택만으로 제목을 자동 완성하지 않는다.

| 분야 | 세부 항목 | 추가 필수 정보 |
| --- | --- | --- |
| 미디어 / 문화 | 영화 | 작품명, 감독 |
| 미디어 / 문화 | 책 | 책 제목, 저자 |
| 미디어 / 문화 | OTT · 방송 · 예능 | 프로그램명 |
| 취미 / 소비 | 여행 · 산행, 쇼핑, 먹거리 · 맛집, 취미 · 기타 경험 | 경험의 배경 |
| 연애 / 사랑 | 연애 · 관계 고민, 부부 · 결혼 생활 | 공개하고 싶은 상황 |
| 커리어 / 진로 | 직장 생활, 취업 · 이직, 커리어 · 진로 | 현재 고민의 배경 |
| 재테크 / 경제 | 주식 · 투자, 저축 · 자산 관리, 경제 전반 | 관심을 갖게 된 배경 |
| 사회 / 이슈 | 최근 사회 이슈, 생활 · 사회 변화 | 이슈의 배경·시점 |

모든 분야는 **방을 만든 이유·배경**과 **함께 나누고 싶은 이야기**를 각각 1~600자로 입력해야 한다. 미디어는 작품 정보로 동명 작품을 구분하고, 그 외 분야는 배경 입력의 예시를 바꿔 방장의 의도를 설명하도록 돕는다. 분야·세부 항목을 바꾸면 기존 작품명·감독/저자는 비워 잘못된 대상을 전달하지 않는다. 입력한 배경과 방향은 유지해 방장이 다듬을 수 있다.

열린 수다방 카드는 `방 소개 보기`로 작품 정보, 선정 이유와 대화 방향을 펼쳐 볼 수 있다. 이 소개는 로그인 전에도 공개되는 방 정보다. 대화방에서는 `방장이 소개하는 오늘의 대화`를 펼쳐 같은 내용을 확인한다. 소개는 기본적으로 접혀 있어 풍경과 현재 대화를 가리지 않는다. 기존 방은 소개 없이 계속 사용할 수 있다.

## AI에 전달하는 내용

`voice_lounge_rooms.topic_brief`에 `category`, `subcategory`, `work_title`, `creator`, `reason`, `discussion`을 저장한다. 새 생성 화면은 일곱 인자 `create_voice_lounge`를 호출한다. 클라이언트와 DB가 필수 항목·자료형·길이·분야/세부 항목 조합을 검증한다. 검증 실패 시 방과 가입 데이터는 생성되지 않는다.

사전 조사 요청은 DB가 발급한 study ticket의 방 제목과 소개를 사용한다. 실제 진행도 DB에 저장된 소개와 기존 조사 결과를 함께 전달한다. 브라우저에서 API 요청에 임의로 넣은 소개는 사용하지 않는다. 소개는 검증된 사실이나 실행할 명령이 아니라 방장의 관심과 대화 맥락으로 다룬다.

구조화된 소개를 조사·사회자 요청의 입력에 더한다. 영화는 검색 후 원문을 실제 읽어 [장면별 대화 카드](./lounge-film-discussion-study.md)를 만드는 분석 요청이 추가될 수 있다. 사전 자료는 방에 한 번 저장해 재사용하며 매 발언마다 검색하지 않는다. 경제·사회 자료에는 시점과 근거를 확인하고, 개인의 관계·진로 사연 자체를 웹에서 조사하거나 진단하지 않는다. 그룹 단계의 기본 질문도 특정 영화·여행·음식에 한정하지 않는다. 미디어 대화는 감상 후기를 전제로 결말·반전을 허용한다.

## 적용

Supabase **SQL Editor**에서 기존 마이그레이션 적용 후 `supabase/migrations/20261004000000_voice_lounge_topic_briefs.sql` 전체를 실행한다. DB 변경을 먼저 적용하고 프런트엔드와 API를 함께 배포한다. 이 파일은 다시 실행할 수 있다. 기존 생성 함수와 기존 방 데이터는 보존한다.

새 SQL을 적용하지 않으면 새로운 생성 화면의 일곱 인자 RPC와 `topic_brief`를 읽는 사회자 API를 사용할 수 없다. 방 소개 없이 생성하는 방식으로 자동 우회하지 않는다.

## 검증

- `scripts/lounge-api.test.mjs`: 소개 검증, 저장된 소개의 조사·진행 전달, 브라우저에서 위조한 소개 무시, 기존 호출 수 유지.
- `scripts/lounge-topic-brief-sql-check.mjs`: 실제 PostgreSQL 환경에서 모든 세부 항목 생성, 필수 항목·형식·길이 검증, 기존 생성 함수, 공개 목록의 데이터 범위, 방장 권한, 재실행.
- `scripts/lounge-ui-check.mjs`: 320~1440px 화면에서 필드 변경·필수 입력과 목록 소개 확인.
- `scripts/lounge-session-browser-check.mjs`: 실제 생성 컴포넌트의 영화·책·다른 분야 전송과 대화방 소개 펼치기, 기존 발언·보호 흐름.

SQL 검증은 격리된 PGlite를 사용하며 실제 Supabase에는 연결하지 않는다. API와 브라우저 검증에는 모의 응답을 사용하므로 유료 AI 호출은 발생하지 않는다.
