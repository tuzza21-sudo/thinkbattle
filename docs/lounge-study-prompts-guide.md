# 사전 준비 프롬프트와 주제별 개선안

현재 구현 기준: 2026-10-04. 아래에서 ‘현재’는 적용된 코드, ‘개선안’은 아직 적용하지 않은 제안이다.

## 프롬프트를 확인할 위치

- 모든 주제의 공통 사전 조사: `src/lib/loungeStudy.ts`의 `loungeStudyInstructions`.
- 영화의 추가 검색 지시: `src/lib/loungeFilmStudy.ts`의 `loungeFilmDiscoveryInstructions`.
- 실제 원문을 읽은 후 영화 장면 카드 분석: 같은 파일의 `loungeFilmAnalysisInstructions`.
- 요청에 프롬프트·자료를 전달하는 연결: `api/lounge.ts`의 `action === 'prepare'` 분기.
- 조사 결과를 대화에서 사용하는 사회자 공통 지시: `api/lounge.ts`의 `action === 'host'` 분기. 진행자 개성은 `src/lib/lounge.ts`의 각 `instruction`에 있다.

SQL은 조사 결과의 형식·출처 목록·권한을 검증한다. SQL 파일에 LLM 조사 프롬프트가 들어 있지는 않다. 실행되는 정확한 전체 문구는 위 변수에서 확인할 수 있다.

## 현재 공통 조사 지시의 내용

방장이 저장한 category·subcategory·work_title·creator·reason·discussion을 사용한다. 방장의 설명을 사실로 인정하지 않고 작품·대상을 웹 검색으로 확인한다. 개인정보나 사연 당사자는 검색하지 않는다.

확인된 사실 3~6개, 해석 관점 3~5개, 구체적 질문 5개를 준비한다. 공식 제작사·배급사·출판사 자료를 우선하고 신뢰할 만한 비평을 참고한다. 최신 자료는 날짜·맥락을 확인한다. 작품의 결말·반전은 허용하고, 근거 없는 장면이나 대사는 만들지 않는다. 대상이 모호하면 확인된 것처럼 설명하지 않고 식별 질문을 준비한다.

현재 다른 분야에 주는 지시는 다음과 같다.

| 분야 | 현재 준비 방향 |
| --- | --- |
| 책·소설 | 첫인상, 인물의 선택·저자의 생각, 표현 방식, 해석의 차이, 참여자 경험 |
| 취미·취향 | 경험·취향·선택을 중심으로 구체적 질문 |
| 연애·사랑 | 본인이 공개한 상황에서 서로 이해할 지점, 일반적인 맥락. 진단·타인의 속마음은 단정하지 않음 |
| 커리어·진로 | 경험과 선택의 기준 |
| 재테크·경제 | 개념·위험 인식·경험, 자료 기준 날짜. 성과 보장·특정 상품 매수 권유는 하지 않음 |
| 자녀·교육 | 아이의 연령대·교육 단계와 방장의 상황을 바탕으로 성장·부모와의 소통·학습 환경·선택 기준. 교육부·교육청·공공 연구기관 자료와 연구의 대상·한계·기준 날짜 확인 |

새 방의 미디어 선택은 영화·책만 제공하고, 나머지 다섯 분야에는 세부 분류 선택이 없다. 방장이 직접 적은 제목·계기·대화 방향으로 조사 범위를 정한다. 이전 사회·이슈·방송 방의 자료는 원래 의미를 유지한다.

자녀·교육에서는 연령대를 추정하지 않고 필요한 질문으로 확인한다. 아이·학교·교사의 신원을 검색하거나 진단·성격·학습 성과를 단정하지 않는다. 개인 경험, 연구 사실, 전문가 해석을 구분한다.

영화 외 주제는 현재 이 공통 검색 요청 한 번으로 준비한다. 분야별 원문 수집·대화 카드 분석을 각각 수행하는 구조는 아직 없다. 참고 사이트도 영화처럼 특정 목록으로 제한하지 않는다.

## 현재 영화 지시의 내용과 자료원

첫 단계는 작품명·감독·연도로 작품을 구별하고, 작품명+감독 / 결말 해석 / 감독 인터뷰 / 장면 분석으로 검색하도록 지시한다. 필요하면 원제를 사용하고 방장이 적은 선정 이유와 대화 방향을 반영한다.

| 자료원 | 현재 활용하도록 지시한 내용 |
| --- | --- |
| TMDB | 식별 정보, 연도·장르·기본 줄거리 |
| KMDb·한국영상자료원 | 비평, 작품 맥락, 감독 인터뷰 |
| 씨네21 | 비평, 작품 기사, 감독 인터뷰 |
| BFI Deep Focus | 감독·장르·영화사 분석 |
| Criterion Essays·Visual Analysis | 작품과 화면·소리·편집 분석 |

모든 사이트에 해당 작품의 자료가 있다고 가정하지 않는다. 서버는 검색이 실제 반환한 해당 도메인의 개별 페이지를 GET으로 읽는다. 최대 6개 후보를 요청해 읽힌 최대 4개 원문의 본문 일부(각 최대 8,000자)를 다음 분석 요청에 전달한다. TMDB API를 직접 연결한 것은 아니며 공개 페이지를 사용한다. 접근 차단·짧은 본문·미확인 자료는 원문 분석 근거에 넣지 않는다.

두 번째 단계는 다음 내용을 요구한다.

> 오직 서버가 읽은 원문에서 확인한 장면을 사용한다. 인물의 욕망과 선택, 관계와 권력, 시점과 정보, 화면·소리·편집, 결말과 상반된 해석을 검토한다. 근거가 없는 축을 억지로 채우지 않는다.

기본 3개, 최대 5개의 카드에 장면·갈등·근거·해석 2~3개·쉬운 감상 질문·답변 방향에 따른 후속 질문 2~3개를 담는다. 각 카드에는 실제 읽은 출처가 있는 장면 사실이 필요하다. 근거 유형은 장면 사실 / 감독의 직접 설명 / 평론가의 해석 / AI 추론으로 구분한다. 자료가 부족하면 확인된 카드만 만들며, 확인된 장면이 없으면 카드 없이 제한된 준비 상태로 저장한다.

이 구조는 ‘모델이 영화를 직접 봤다’거나 ‘영화학을 새로 학습했다’는 의미가 아니다. 읽은 자료를 정리해 해당 방의 대화 맥락으로 전달한다. 검증은 출처 연결과 데이터 형식의 검증이며 해석의 정확성을 자동으로 보증하지 않는다.

## 다른 주제의 깊이를 높이는 개선안

깊이는 검색량뿐 아니라 ‘무엇을 비교하고 무엇을 물을지’에서 나온다. 영화 카드의 장면을 각 분야의 구체적인 사례·논점으로 바꾸는 것이 좋다.

| 분야 | 준비할 구체적 단위 | 자료 우선순위 | 대화 질문 방향 |
| --- | --- | --- | --- |
| 책 | 저자의 핵심 주장, 이를 받치는 사례, 반례, 독자의 다른 해석 | 원문·출판사, 저자 인터뷰, 신뢰할 만한 서평 | 어느 주장에 동의하기 어려웠는지, 자기 경험과 어디서 달라졌는지 |
| 여행·산행·쇼핑·맛집 | 같은 조건에서 서로 다른 선택, 만족·후회의 이유 | 해당 장소·업체의 공식 정보, 날짜가 명확한 경험 자료 | 비용·시간·동행·취향 중 무엇이 경험을 바꿨는지 |
| 연애·부부 | 공개된 상황, 충돌하는 욕구, 경계와 기대의 차이 | 일반적인 소통 연구·교육 자료. 사연 당사자 검색 금지 | 어떤 말·행동을 서로 다르게 받아들였는지, 무엇을 이해받고 싶은지 |
| 커리어·진로 | 선택지의 대가, 역량·환경·가치의 충돌, 상황별 반례 | 직무·산업 공식 자료, 공개 연구·통계, 출처가 있는 경험 | 같은 결정을 다른 경력 단계나 생활 조건에서도 할지 |
| 재테크·경제 | 개념·가정·시나리오, 손실 가능성, 다른 해석 | 기관 통계·공시·공식 상품 설명. 모든 수치는 기준일 명시 | 어떤 가정이 틀리면 판단이 달라지는지, 각자의 위험 인식은 무엇인지 |
| 자녀·교육 | 아이의 연령대·교육 단계, 실제 고민, 시도한 방법과 변화, 서로 다른 선택 | 교육부·교육청·공공 교육 연구기관과 공개 연구. 대상·지역·기준일·연구 한계 명시 | 아이와 부모가 원하는 것, 해 본 방법의 차이, 가정에서 지키고 싶은 기준 |

분야별 분석 프롬프트는 다음 공통 골격을 사용할 수 있다. 실제 적용 시 분야 지시와 구조화된 JSON 스키마를 별도로 붙인다.

```text
방장의 선정 이유와 궁금한 점을 중심으로 구체적 대화 카드 3~5개를 준비한다.
입력 자료에 근거한 사례·사건·주장만 사용한다.
사실, 당사자의 직접 설명, 전문가의 해석, AI 추론을 구분한다.
각 카드에 서로 충돌하는 기준이나 욕구, 가능한 관점 2~3개와 근거를 담는다.
출처와 자료 기준 날짜를 기록하며 부족한 근거는 부족하다고 표시한다.
누구나 자기 경험이나 판단으로 답할 수 있는 질문 하나를 준비한다.
서로 다른 답변 방향 2~3개에 대한 후속 질문을 준비한다.
아직 참가자가 그렇게 답했다고 가정하지 않는다.
사연 당사자를 조사하거나 타인의 속마음을 사실처럼 단정하지 않는다.
반대 관점을 억지로 동등하게 만들지 말고 근거의 질과 불확실성을 구분한다.
출처에 없는 사례나 수치를 채워 넣지 않는다.
```

공통 준비 수준은 가벼운 탐색 / 근거를 비교하는 준비로 구분하고, 작품 분석이나 최신 쟁점처럼 필요한 방에서만 원문 분석 단계를 추가하는 편이 좋다. 저장된 자료는 방에서 재사용하며, 모든 발언마다 추가 검색을 수행하면 대화가 느려질 수 있다.

사회자는 응답할 때 참가자의 말을 요약해서 반복하는 대신 실제로 나온 선택·감정·기준에 맞는 카드 한 개를 선택한다. 공감, 구체화, 다른 관점의 제안, 참가자끼리의 연결 중 필요한 개입 하나를 한다. 사람끼리 대화하는 방에서는 매 발언에 응답하지 않는다. 첫 질문 뒤에는 기다리고, 직접 도움을 요청하거나 침묵이 길어질 때만 준비한 자료를 활용한다. 자기소개와 마지막 정리만 순서 발언을 사용하며 중간은 자유 대화다. 구현과 SQL 적용은 [사람끼리 이야기하는 라운지의 AI 역할](./lounge-human-conversation.md)을 참고한다. 자료를 많이 준비하는 것만으로 개입 타이밍 문제까지 해결되지는 않는다.
